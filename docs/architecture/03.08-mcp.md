# MCP — 外部能力适配

---

## § 职责定位

MCP 模块负责把外部 MCP Server 暴露为 MindClaw Tool System 中的工具适配器，不负责 Agent 路由、上下文构建或工具权限决策。

---

## § 在新架构中的位置

MCP 属于 Adapter Layer：

- 上游被 ToolRegistry 视为一组 `ToolAdapter`
- 下游连接 stdio 或 HTTP 的 MCP Server

它不属于 AgentProfile，也不属于 AgentRunner 本身。

---

## § 核心对象

**MCPManager**

- 读取 MCP 配置
- 管理 Server 连接与重连
- 发现远端工具列表
- 为每个远端工具创建 ToolAdapter

**MCPToolAdapter**

- 实现 Tool 接口
- 把调用转发给对应 MCP Server
- 把返回值转成统一 ToolResult

---

## § 与工具系统的关系

```text
MCP Server
-> MCPManager
-> MCPToolAdapter
-> ToolRegistry
-> ToolExecutor
-> AgentRunner
```

MCP 工具和内置工具在执行层面等价，只是来源不同。

---

## § 设计决策与权衡

| 决策问题 | 选择 | 放弃的替代方案 | 理由 |
|---------|------|--------------|------|
| MCP 处于哪一层？ | Adapter Layer | Agent Runtime Core | MCP 是外部协议接入，不是核心运行时语义 |
| MCP 工具如何暴露？ | 作为 ToolAdapter 注册进 ToolRegistry | AgentRunner 直接调 MCPManager | 统一工具执行入口后，限流、超时、审计逻辑都可复用 |
| MCP 权限由谁控制？ | AgentProfile + Tool filtering | MCPManager 自己决定 | 权限控制应该统一，不应让单个 adapter 成为策略源 |
