# Chat 悬浮覆盖

→ 架构关联：[08-desktop-frontend.md](../arch/08-desktop-frontend.md)  
→ 父文档：[00-overview.md](00-overview.md)

## 背景与目标

**背景**：MindClaw 的核心 UX 原则是"对话是万能入口"——用户通过自然语言表达意图，Agent 负责执行（创建任务、追加日记、生成知识笔记）。Chat 入口必须随时可达，但不能占据独立页面打断当前工作流，因此采用悬浮覆盖形式。

**目标**：定义 Chat 悬浮卡片的触发、对话、交互模式切换、流式回复展示等核心行为。

## 功能描述

### US-01 打开和关闭 Chat 窗口

作为用户，我希望随时打开/关闭 Chat 窗口，以便在不切换页面的情况下与 Agent 对话。

**验收标准**：

Given 用户处于工作区任意状态  
When 用户点击右上角 "chat" 按钮  
Then Chat 卡片窗口出现，覆盖中央内容区（左侧导航栏和右侧面板仍然可见），输入框自动获得焦点

Given Chat 卡片窗口已打开  
When 用户再次点击右上角 "chat" 按钮，或点击卡片右上角关闭按钮  
Then Chat 卡片窗口关闭，中央内容区恢复显示

- [ ] "chat" 按钮始终固定在窗口右上角，在工作区的任意状态下可见
- [ ] Chat 卡片窗口打开时，背后的工作区内容不可交互（不可点击、不可滚动）
- [ ] Chat 卡片窗口打开/关闭有淡入淡出动效，持续时间 150ms

**优先级**：P0

---

### US-02 发送消息

作为用户，我希望在 Chat 窗口中输入消息并发送，以便向 Agent 提问或发出指令。

**验收标准**：

Given Chat 窗口已打开  
When 用户在输入框输入文字并按 Enter 键（或点击发送按钮）  
Then 用户消息立即显示在消息列表中，输入框清空，Agent 开始处理

- [ ] 输入框支持多行输入（Shift+Enter 换行）
- [ ] 消息发送后输入框立即清空，不需要等待 Agent 回复
- [ ] 输入框为空时发送按钮禁用，不可点击
- [ ] 用户消息显示在消息列表右侧

**优先级**：P0

---

### US-03 接收流式回复

作为用户，我希望 Agent 的回复以流式方式逐字出现，以便在回复完成前就能开始阅读。

**验收标准**：

Given 用户已发送消息  
When Agent 开始生成回复  
Then 消息列表中显示 Agent 消息气泡，文字内容随 Agent 输出逐步追加

Given Agent 正在生成回复  
When 回复尚未完成  
Then Agent 消息气泡显示当前阶段状态：

- 思考中（LLM 首次 token 前）：显示"思考中..."动效
- 工具调用中：显示"处理中..."动效
- 文字生成中：在最后一个字符后显示光标动效

Given Agent 回复完成  
When 最后一个 token 到达  
Then 光标动效消失，消息显示为完成态（支持 Markdown 渲染）

- [ ] 流式回复中用户可继续滚动查看历史消息
- [ ] 流式回复完成前不显示"重新生成"按钮
- [ ] Markdown 语法（加粗、代码块、列表）在回复完成后正确渲染

**优先级**：P0

---

### US-04 交互模式切换

作为用户，我希望在发送消息前选择交互模式，以便控制 Agent 的回应风格。

**验收标准**：

Given Chat 窗口已打开  
When 用户点击模式切换区域中的某个模式标签  
Then 该模式高亮为选中态，之后发送的消息均使用该模式

- [ ] 模式选择区域显示 5 个可点击标签：陪伴 / 反思 / 挑战 / 知识 / 树洞
- [ ] 默认选中"陪伴"模式
- [ ] 选中"树洞"模式时，输入框背景色改变（区别于其他模式），提示文字为"树洞内容不进知识库"
- [ ] 模式切换即时生效，不需要重新打开 Chat 窗口
- [ ] 切换模式不清除当前会话的消息历史

**5 种模式定义**：

| 模式 | 标签 | Agent 行为 |
|------|------|-----------|
| 陪伴 | 陪伴 | 接收、共情、不评判、不提建议 |
| 反思 | 反思 | 带出观察、提问、轻推，不给结论 |
| 挑战 | 挑战 | 直接指出模式，给出判断，有明确立场 |
| 知识 | 知识 | 共建知识笔记，结晶为可存储的结构 |
| 树洞 | 树洞 | 接收持有，内容不进共有知识库 |

**优先级**：P1

---

### US-05 查看会话历史

作为用户，我希望在 Chat 窗口中向上滚动查看本次会话的历史消息，以便了解对话上下文。

**验收标准**：

- [ ] Chat 窗口内消息列表支持垂直滚动
- [ ] 打开 Chat 窗口时，消息列表默认滚动到最新消息位置
- [ ] 新消息到达时，若用户未手动滚动到历史位置，则自动滚动到底部；若用户已向上滚动，则不自动滚动

**优先级**：P1

## 范围界定

**In Scope**：

- Chat 悬浮卡片的打开/关闭
- 用户消息发送
- Agent 流式回复展示（含阶段动效）
- 5 种交互模式切换
- 会话内消息历史滚动查看

**Out of Scope**：

- 多会话管理（新建/切换/删除会话）：Phase 1 只有单一持续会话；多会话功能在流式回复稳定后引入
- 语音输入：依赖系统 API，不在当前版本范围内
- 图片/文件上传：Agent 当前工具集不支持处理上传文件，排除
- 消息搜索：会话内搜索优先级低，排除

## 非功能需求

- Chat 窗口从点击按钮到出现（含动效）的时间 ≤ 200ms
- 用户消息发送到 Agent 第一个 token 出现的时间 ≤ 3 秒（依赖 LLM 服务响应速度，前端不做人为延迟）
- Chat 卡片尺寸：宽度固定 480px，高度固定 560px，不可拖拽调整大小（Phase 1）
