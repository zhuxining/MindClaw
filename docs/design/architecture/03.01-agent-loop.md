# AgentLoop — 业务编排层

> 消息消费、会话管理、并发控制与流式分发

## 职责定位

AgentLoop 是 MindClaw 的业务编排层，负责：

- 从 MessageBus 消费入站消息
- 按 session 串行化执行
- 解析命令和取消请求
- 读取 session + memory refs
- 构造 `AgentRunSpec`
- 调用 `AgentRunner` 执行核心循环
- 结果持久化与流式分发

**核心原则**：AgentLoop 不执行工具，也不维护复杂任务状态，只负责编排。

## 架构位置

```
Channel ──► MessageBus ──► AgentLoop ──► AgentRunner
                               │
                               ├── SessionManager
                               ├── MemoryStore
                               ├── ContextBuilder
                               └── CommandRouter
```

## 核心结构

```rust
pub struct AgentLoop {
    // 基础设施
    bus: Arc<MessageBus>,
    session_manager: Arc<SessionManager>,
    memory_store: Arc<MemoryStore>,

    // 上下文构建（三层架构）
    core_cache: CoreLayerCache,
    dynamic_sources: Vec<Arc<dyn ContextSource>>,
    user_layer: UserLayerBuilder,

    // 执行层
    runner: Arc<AgentRunner>,

    // 并发控制
    session_locks: DashMap<String, Arc<tokio::sync::Mutex<()>>>,
    concurrency_gate: Arc<tokio::sync::Semaphore>,

    // 活跃任务跟踪
    active_tasks: DashMap<String, tokio::task::JoinHandle<()>>,
}
```

## 消息处理流程

### 主循环

```rust
impl AgentLoop {
    pub async fn run(&self) {
        loop {
            // 1. 消费入站消息（1秒超时）
            match self.bus.consume_inbound().await {
                Some(message) => self.dispatch(message).await,
                None => continue,
            }
        }
    }
}
```

### 消息分发

```rust
impl AgentLoop {
    async fn dispatch(&self, message: InboundMessage) {
        let session_key = message.session_key();
        
        // 1. 检查是否为优先级命令（如 /stop）
        if self.is_priority_command(&message) {
            self.handle_command(message).await;
            return;
        }
        
        // 2. 包装为异步任务
        let task = tokio::spawn(async move {
            self.process_message(message).await;
        });
        
        // 3. 跟踪活跃任务
        self.active_tasks.insert(session_key, task);
    }
}
```

### 消息处理管线

```rust
impl AgentLoop {
    async fn process_message(&self, message: InboundMessage) {
        let session_key = message.session_key();
        
        // 1. 双层并发控制
        let session_lock = self.get_session_lock(&session_key);
        let _permit = self.concurrency_gate.acquire().await;
        let _guard = session_lock.lock().await;
        
        // 2. 获取或创建会话
        let session = self.session_manager.get_or_create(&session_key).await;
        
        // 3. 检查斜杠命令
        if let Some(result) = self.command_router.handle(&message, &session).await {
            self.send_response(&session_key, result).await;
            return;
        }
        
        // 4. 记忆整合（如需要）
        self.maybe_consolidate_memory(&session).await;
        
        // 5. 召回相关记忆
        let memory_refs = self.memory_store.recall(&message.content).await;
        
        // 6. 构建上下文
        let spec = self.build_run_spec(&message, &session, memory_refs).await;
        
        // 7. 创建内部钩子（桥接两层）
        let mut hook = LoopHook::new(
            self.bus.clone(),
            session_key.clone(),
            message.channel_context(),
        );
        
        // 8. 执行 Agent 循环
        let result = self.runner.run(spec, &mut hook).await;
        
        // 9. 持久化 turn
        self.session_manager.append_turn(&session_key, &result).await;
        
        // 10. 发送响应
        self.send_result(&session_key, result).await;
        
        // 11. 清理任务跟踪
        self.active_tasks.remove(&session_key);
    }
}
```

## 并发控制模型

### 双层并发控制

```
InboundMessage
    │
    ▼
[获取并发闸许可] ──► Semaphore(3)
    │
    ▼
[获取会话锁] ──► DashMap<session_key, Mutex>
    │
    ▼
_process_message()
```

### 实现细节

```rust
impl AgentLoop {
    // 获取或创建会话锁
    fn get_session_lock(&self, session_key: &str) -> Arc<tokio::sync::Mutex<()>> {
        self.session_locks
            .entry(session_key.to_string())
            .or_insert_with(|| Arc::new(tokio::sync::Mutex::new(())))
            .clone()
    }
}
```

**设计理由**：

- **Session Lock**：确保同一会话的消息按顺序处理，保持对话连贯性
- **Concurrency Gate**：限制全局并行 LLM 请求数（默认 3），防止耗尽提供商速率限制

## 上下文组装（三层架构）

AgentLoop 采用三层上下文架构构建消息列表：

```
第 1 层（Core）：SOUL.md / USER.md / AGENTS.md / 工具 Schema（缓存稳定）
第 2 层（Dynamic）：Identity / Memory / Knowledge / Skills（每次请求变化）
第 3 层（User）：运行时上下文 + 用户输入（每次请求唯一）
```

详见 [03.06-context-building.md](./03.05-agent-context.md)。

### 三层构建流程

```rust
impl AgentLoop {
    async fn build_run_spec(
        &self,
        message: &InboundMessage,
        session: &Session,
    ) -> AgentRunSpec {
        // 构建消息列表（三层架构）
        let messages = self.build_messages(message, session).await;

        // 获取活跃工具
        let tools = self.get_active_tools(&message.channel_context());

        AgentRunSpec {
            messages,
            tools,
            model: session.settings.model.clone(),
            max_iterations: 8,
            temperature: session.settings.temperature,
            max_tokens: None,
            parallel_tools: true,
            fail_on_tool_error: false,
        }
    }

    async fn build_messages(
        &self,
        inbound: &InboundMessage,
        session: &Session,
    ) -> Vec<Message> {
        let mut messages = Vec::new();

        // 第 1 层：核心稳定（从缓存获取）
        let core_message = self.core_cache.get_or_build(&self.core_builder);
        messages.push(core_message);

        // 第 2 层：动态上下文（按优先级排序）
        let ctx = BuildContext {
            session,
            inbound,
            history: vec![],
        };

        let mut dynamic_sources: Vec<_> = self.dynamic_sources
            .iter()
            .filter(|s| s.layer() == ContextLayer::Dynamic)
            .collect();
        dynamic_sources.sort_by_key(|s| s.priority());

        for source in dynamic_sources {
            let msgs = source.inject(&ctx).await;
            messages.extend(msgs);
        }

        // 会话历史（已压缩）
        let history = self.session_manager.compressed_history(session).await;
        messages.extend(history);

        // 第 3 层：用户消息
        messages.push(self.user_layer.build(inbound));

        messages
    }
}
```

### 核心层缓存

```rust
pub struct CoreLayerCache {
    message: Option<Message>,
    hash: String,
}

impl CoreLayerCache {
    pub fn get_or_build(&mut self, builder: &CoreLayerBuilder) -> Message {
        let new_hash = builder.hash();
        if self.hash != new_hash {
            self.message = Some(builder.build());
            self.hash = new_hash;
        }
        self.message.clone().unwrap()
    }
}
```

**设计理由**：

- 第 1 层（Core）缓存稳定，支持 LLM Provider 的 KV-cache 复用
- 第 2 层（Dynamic）每次请求变化，包含 Memory 和 Knowledge
- 第 3 层（User）每次请求唯一，包含运行时上下文

## 流式分发

### 基于分段的流式模型

```rust
pub struct LoopHook {
    bus: Arc<MessageBus>,
    session_key: String,
    segment_id: u64,
    buffer: String,
    last_stripped_len: usize,
}

impl AgentHook for LoopHook {
    fn on_stream(&mut self, delta: &str) {
        // 1. 缓冲原始内容
        self.buffer.push_str(delta);
        
        // 2. 剥离 think 标签（差分剥离）
        let stripped = strip_think_tags(&self.buffer);
        let new_chars = &stripped[self.last_stripped_len..];
        
        // 3. 只发送新增的清洁字符
        if !new_chars.is_empty() {
            self.bus.publish(OutboundMessage::Chunk {
                session_key: self.session_key.clone(),
                segment_id: self.segment_id,
                content: new_chars.to_string(),
            });
            self.last_stripped_len = stripped.len();
        }
    }
    
    fn on_stream_end(&mut self, resuming: bool) {
        self.bus.publish(OutboundMessage::SegmentEnd {
            session_key: self.session_key.clone(),
            segment_id: self.segment_id,
            resuming,
        });
        
        if resuming {
            // 还有工具调用，新分段
            self.segment_id += 1;
            self.buffer.clear();
            self.last_stripped_len = 0;
        }
    }
}
```

**设计理由**：

- **分段模型**：支持多段响应（文本段 → 工具调用段 → 文本段）
- **差分剥离**：正确处理 think 标签跨多个增量开启的情况
- **段计数器**：为 UI 层提供清晰的边界

## 命令处理

### 优先级命令

优先级命令（如 `/stop`）在主循环任务上同步分发，绕过并发控制：

```rust
impl AgentLoop {
    fn is_priority_command(&self, message: &InboundMessage) -> bool {
        message.content.starts_with("/stop") ||
        message.content.starts_with("/restart")
    }
    
    async fn handle_command(&self, message: InboundMessage) {
        match message.content.as_str() {
            "/stop" => self.handle_stop(&message.session_key()).await,
            "/restart" => self.handle_restart(&message.session_key()).await,
            _ => {}
        }
    }
    
    async fn handle_stop(&self, session_key: &str) {
        // 取消活跃任务
        if let Some((_, task)) = self.active_tasks.remove(session_key) {
            task.abort();
        }
        
        // 发送停止确认
        self.bus.publish(OutboundMessage::Status {
            session_key: session_key.to_string(),
            status: RunStatus::Stopped,
        });
    }
}
```

### 普通斜杠命令

普通命令（如 `/new`, `/status`）在 `_process_message` 中处理：

```rust
impl AgentLoop {
    async fn handle_slash_command(&self, message: &InboundMessage, session: &Session) -> Option<String> {
        let parts: Vec<&str> = message.content.split_whitespace().collect();
        let command = parts.get(0)?;
        
        match *command {
            "/new" => {
                self.session_manager.create_new(&message.session_key()).await;
                Some("已创建新会话".to_string())
            }
            "/status" => {
                let status = self.session_manager.get_status(session).await;
                Some(format!("当前会话: {} 轮对话", status.turn_count))
            }
            _ => None,
        }
    }
}
```

## 记忆整合

### 触发条件

```rust
impl AgentLoop {
    async fn maybe_consolidate_memory(&self, session: &Session) {
        // 估算 token 数
        let estimated_tokens = self.estimate_tokens(session);
        let budget = session.settings.context_budget;
        
        // 接近预算时触发整合
        if estimated_tokens > budget * 0.8 {
            tokio::spawn(async move {
                self.memory_store.consolidate(session).await;
            });
        }
    }
}
```

## 轮次持久化

### 内容清理

```rust
impl AgentLoop {
    async fn append_turn(&self, session_key: &str, result: &AgentRunResult) {
        // 清理消息内容
        let cleaned_messages: Vec<Message> = result.messages.iter()
            .map(|m| self.clean_message(m))
            .collect();
        
        // 保存到会话
        self.session_manager.append_turn(session_key, cleaned_messages).await;
    }
    
    fn clean_message(&self, message: &Message) -> Message {
        match message {
            Message::ToolResult { content, .. } => {
                // 截断过长的工具结果
                if content.len() > 16000 {
                    Message::ToolResult {
                        content: format!("{}... [truncated]", &content[..16000]),
                        ..message.clone()
                    }
                } else {
                    message.clone()
                }
            }
            Message::User { content, .. } => {
                // 移除 base64 图像
                let cleaned = remove_base64_images(content);
                Message::User { content: cleaned, ..message.clone() }
            }
            _ => message.clone(),
        }
    }
}
```

## 关闭处理

```rust
impl AgentLoop {
    pub async fn shutdown(&self) {
        // 1. 停止消费新消息
        self.bus.close_inbound();
        
        // 2. 等待活跃任务完成
        let tasks: Vec<_> = self.active_tasks.iter()
            .map(|entry| entry.value().clone())
            .collect();
        
        for task in tasks {
            let _ = task.await;
        }
        
        // 3. 清理资源
        self.session_locks.clear();
    }
}
```

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 并发模型 | Session Lock + Concurrency Gate | 保证会话串行，同时限制全局并发 |
| 流式模型 | 基于分段 | 支持多段响应，清晰边界 |
| 命令处理 | 优先级命令同步，普通命令异步 | 控制命令必须能中断处理流程 |
| 记忆整合 | 异步后台执行 | 不阻塞主响应 |
| 内容清理 | 持久化前执行 | 保持会话数据整洁 |
