# Skills 系统

> 基于 [Agent Skills](https://agentskills.io) 规范的能力扩展机制

## 设计哲学

- **标准化**：遵循 Agent Skills 规范，兼容 Claude Code 等工具
- **渐进式披露**：元数据启动加载 → 指令激活加载 → 资源按需加载
- **自包含**：每个技能是独立目录（SKILL.md + scripts/ + references/ + assets/）
- **可发现**：通过 `name` 和 `description` 自动匹配用户意图

## 目录结构

```
skills/
├── github/
│   ├── SKILL.md          # 必需：元数据 + 指令
│   ├── scripts/          # 可选：可执行脚本
│   ├── references/       # 可选：参考文档
│   └── assets/           # 可选：模板、资源
└── weather/
    └── SKILL.md
```

## SKILL.md 格式

详见 [Agent Skills 规范](https://agentskills.io)。关键字段：

| 字段 | 必需 | 说明 |
|------|------|------|
| `name` | ✅ | 1-64字符，小写/数字/连字符，匹配目录名 |
| `description` | ✅ | 1-1024字符，说明**做什么**和**何时使用** |
| `license` | ❌ | 许可证 |
| `compatibility` | ❌ | 环境要求 |
| `metadata` | ❌ | 扩展字段（`always_load`, `category`, `author` 等） |
| `allowed-tools` | ❌ | 预批准工具列表 |

### 示例

```markdown
---
name: github-integration
description: |
  与 GitHub API 交互，管理仓库、Issue、PR。
  当用户提到 GitHub、仓库、Issue、PR 时使用。
metadata:
  author: mindclaw
  category: dev
  always_load: false
---
```

## 核心设计

### 渐进式披露

```
启动阶段（~100 tokens）
├── 扫描 skills/ 目录
├── 解析所有 SKILL.md 的 frontmatter（仅 name + description）
└── 构建 metadata_index
    
激活阶段（< 5000 tokens）
├── 根据用户消息匹配技能
├── 激活匹配的技能（加载完整 SKILL.md）
└── 注入到上下文
    
按需加载（额外 tokens）
├── scripts/ 中的脚本
├── references/ 中的参考文档
└── assets/ 中的资源文件
```

### SkillsSource（Context Building）

```rust
pub struct SkillsSource {
    registry: Arc<SkillsRegistry>,
}

impl ContextSource for SkillsSource {
    fn layer(&self) -> ContextLayer { ContextLayer::Dynamic }
    fn priority(&self) -> i32 { 40 }
    
    async fn inject(&self, ctx: &BuildContext) -> Vec<Message> {
        let mut messages = Vec::new();
        
        // 1. 常驻技能：完整内联
        let resident = self.registry.get_resident_skills().await;
        if !resident.is_empty() {
            let content = resident.iter()
                .map(|s| format!("## {}\n{}", s.name, s.content))
                .join("\n\n");
            messages.push(Message::system(format!("## 常驻技能\n{}", content)));
        }
        
        // 2. 可发现技能：仅元数据
        let discoverable = self.registry.get_discoverable_skills();
        if !discoverable.is_empty() {
            let summary = discoverable.iter()
                .map(|s| format!("- {}: {}", s.name, s.description))
                .join("\n");
            messages.push(Message::system(format!(
                "## 可用技能（按需激活）\n{}", summary
            )));
        }
        
        // 3. 根据用户消息匹配并激活
        let matched = self.registry.search(&ctx.inbound.content);
        for metadata in matched.iter().take(3) {
            if resident.iter().any(|r| r.name == metadata.name) {
                continue; // 避免重复
            }
            if let Ok(manifest) = self.registry.activate(&metadata.name).await {
                messages.push(Message::system(format!(
                    "## 相关技能：{}\n{}", manifest.name, manifest.content
                )));
            }
        }
        
        messages
    }
}
```

## 关键设计决策

1. **渐进式披露**：启动只加载元数据（~100 tokens），激活才加载完整指令（< 5000 tokens），资源按需加载
2. **常驻 vs 可发现**：`always_load=true` 的技能完整内联，其他仅显示摘要
3. **目录名约束**：技能 `name` 必须匹配目录名，避免混淆
4. **三层 Context**：Skills 属于 Dynamic 层，每次请求重新评估

## 与相关设计的关系

- **Agent Skills 规范**：遵循标准，但增加 `always_load` 等 MindClaw 特定字段
- **Context Building**：Skills 是 Dynamic 层的重要组成部分，与 Memory、Knowledge 并列
- **Tool System**：Skills 描述"何时使用工具"，Tool Schema 描述"如何使用工具"
