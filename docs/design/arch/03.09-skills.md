# Skills — 能力定义与按需注入

---

## § 职责定位

Skills 系统负责发现技能、加载技能说明，并在 ContextPipeline 中按需注入相关技能内容；不负责注册工具实现或直接驱动执行。

---

## § 在新架构中的位置

Skills 处于 Definition 与 Runtime 之间的增强层：

- 在 Definition 侧，它们提供可复用能力定义
- 在 Runtime 侧，它们通过 ContextPipeline 动态注入

Skills 不是 AgentProfile 本身，但可被多个 AgentProfile 共享。

---

## § 核心对象

**SkillManifest**

- `name`
- `description`
- `always_load`
- `instruction_body`

**SkillsRegistry**

- 发现并缓存技能元数据
- 在请求阶段按需激活技能内容

**SkillsSource**

- ContextPipeline 的一个 Dynamic Source
- 根据 Profile 和用户输入决定注入哪些技能

---

## § 生命周期

1. 启动时扫描技能目录，只加载元数据
2. ContextPipeline 构建时，根据 `AgentProfile.ContextPolicy.include_skills` 决定是否启用
3. 匹配用户输入和当前 Agent 类型
4. 激活技能正文并注入上下文

---

## § 与 AgentProfile 的关系

AgentProfile 不直接内嵌技能全文，只定义：

- 是否允许 skills
- 允许哪些 skills
- 是否有常驻 skills

这样 Profile 保持稳定，技能正文仍然是可独立演进的文档资产。

---

## § 设计决策与权衡

| 决策问题 | 选择 | 放弃的替代方案 | 理由 |
|---------|------|--------------|------|
| Skills 属于哪层？ | Definition 增强 + Runtime 注入 | 直接并入 AgentProfile | Skill 是可复用资产，不应复制进多个 profile |
| Skills 是否负责注册工具？ | 否 | Skills 内嵌工具实现 | 保持“何时使用”与“如何执行”分离 |
| Skills 如何进入运行时？ | ContextPipeline 按需注入 | 启动时全量常驻注入 | 技能数量增长后，全量注入会失控 |
