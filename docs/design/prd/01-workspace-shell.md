# 工作区框架

→ 架构关联：[08-desktop-frontend.md](../arch/08-desktop-frontend.md)

## 背景与目标

**背景**：MindClaw 桌面端需要一个固定的视觉框架，将笔记导航（左）、内容编辑（中）、上下文面板（右）三个关注点在同一窗口内共存，同时保证 Chat 对话入口随时可达，不打断当前工作流。

**目标**：定义用户进入应用后看到的基础工作区布局，以及在其中导航的行为规范。

## 功能描述

### US-01 三栏工作区

作为用户，我希望打开 MindClaw 后看到三栏固定布局，以便在同一窗口内同时感知导航、内容和上下文。

**验收标准**：

- [ ] 应用启动后默认显示三栏布局：左侧导航栏 + 中央内容区 + 右侧面板
- [ ] 左侧导航栏宽度默认 220px，可拖拽调整（范围 160px–320px）
- [ ] 右侧面板宽度默认 260px，可拖拽调整（范围 200px–400px）
- [ ] 三栏布局在窗口宽度 ≥ 900px 时保持完整显示

**优先级**：P0

---

### US-02 Tab 导航切换区域

作为用户，我希望点击左侧的 Tab 按钮切换到不同的内容区域，以便快速在常用目录之间跳转。

**验收标准**：

Given 用户处于工作区框架中  
When 用户点击左侧 Tab 中的任意一项  
Then 该 Tab 高亮显示为选中态，下方目录区域切换为该 Tab 对应的目录内容

Given 用户已在某 Tab 下打开了一个笔记  
When 用户切换到另一个 Tab 再切换回来  
Then 之前打开的笔记仍然保持打开（中央内容区不重置）

**默认 Tab 列表**：

Vault 根目录结构（默认 Tab 对应关系）：

```
{vault}/
├── daily/      ← Daily Tab 的目录范围
├── tasks/      ← Tasks 右侧面板数据来源，不作为独立 Tab
├── private/    ← Private Tab 的目录范围
├── source/     ← Source Tab 的目录范围
└── ...         ← 其他笔记和文件夹（Vault Tab 的额外范围）
```

| Tab | 标签 | 目录区域内容 |
|-----|------|------------|
| Daily | 日记 | `daily/` 下按日期排列的文件列表 |
| Private | 私密 | `private/` 下的文件列表 |
| Vault | 库 | Vault 全文件树（排除隐藏文件和 `.mindclaw/`） |
| Source | 资源 | `source/` 下的资源列表 |

**优先级**：P0

---

### US-03 固定自定义目录为 Tab

作为用户，我希望将 Vault 中任意文件夹固定为 Tab，以便快速访问常用目录，无需每次从 Vault Tab 逐层展开。

**验收标准**：

Given 用户在目录区域的某个文件夹上右键  
When 弹出上下文菜单  
Then 菜单中包含"固定为 Tab"选项

Given 用户点击"固定为 Tab"  
When 操作触发  
Then 该文件夹作为新 Tab 出现在默认 Tab 列表之后，Tab 标签为文件夹名称

Given Tab 导航中存在自定义固定的 Tab  
When 用户右键点击该 Tab  
Then 弹出菜单包含"取消固定"选项；点击后该 Tab 从导航中移除

- [ ] 自定义 Tab 数量上限为 6 个
- [ ] 自定义 Tab 的排列顺序可通过拖拽调整
- [ ] 固定的 Tab 及其顺序持久化存储，应用重启后恢复
- [ ] 默认四个 Tab（Daily / Private / Vault / Source）不可被取消固定

**优先级**：P1

---

### US-04 目录区域视图模式切换

作为用户，我希望在目录区域选择树状或平铺两种视图模式，以便根据使用习惯浏览文件。

**验收标准**：

Given 用户处于任意 Tab 下  
When 用户点击目录区域右上角的视图切换按钮  
Then 目录区域在树状（Tree）和平铺（Flat）两种模式之间切换

**树状模式（Tree）**：

Given 用户处于树状模式  
When 目录区域渲染完成  
Then 文件以层级缩进展示，文件夹可展开/折叠，子文件缩进显示在父文件夹下方

**平铺模式（Flat）**：

Given 用户处于平铺模式  
When 目录区域渲染完成  
Then 当前 Tab 目录范围内的所有文件（含子目录下的文件）以平铺列表展示，不显示文件夹层级，按文件修改时间倒序排列

- [ ] 视图模式选择按 Tab 独立记忆（例如 Daily Tab 用平铺，Vault Tab 用树状）
- [ ] 视图模式选择持久化，应用重启后按 Tab 恢复

**优先级**：P1

---

### US-05 目录区域文件浏览

作为用户，我希望在左侧目录区域点击文件，以便在中央内容区打开对应内容。

**验收标准**：

Given 用户处于任意 Tab 下  
When 用户点击目录区域中的某个文件  
Then 中央区域打开该文件对应的内容视图（Milkdown 编辑器或资源预览）

- [ ] 当前打开的文件在目录区域中以高亮态显示
- [ ] 目录区域支持垂直滚动（文件数量超出可视区域时）
- [ ] 文件名超长时截断显示，hover 展示完整名称

**优先级**：P0

---

### US-06 右侧面板固定区域

作为用户，我希望右侧面板始终显示 Pin、Tasks、Relevance 三个区块，以便在编辑时保持任务和相关内容的可见性。

**验收标准**：

- [ ] 右侧面板包含三个垂直排列的区块：Pin（上）、Tasks（中）、Relevance（下）
- [ ] 三个区块的分隔线可拖拽调整各自高度
- [ ] 每个区块有固定标题行（显示区块名称），内容区可独立滚动
- [ ] 窗口高度 < 600px 时，Relevance 区块自动折叠

**优先级**：P0

---

### US-07 右侧 Pin 区块

作为用户，我希望将某个笔记固定到 Pin 区块，以便在编辑其他内容时快速参照该笔记。

**验收标准**：

Given 用户在目录树或中央区域查看某个笔记  
When 用户点击该笔记的 Pin 按钮  
Then 该笔记标题显示在 Pin 区块中，点击标题在中央区域打开该笔记

Given Pin 区块已有一个笔记  
When 用户 Pin 另一个笔记  
Then 新笔记替换旧笔记（Pin 区块同时只显示一个笔记）

Given Pin 区块有笔记  
When 用户点击 Pin 区块中的取消固定图标  
Then Pin 区块恢复为空状态，显示"点击 Pin 图标固定笔记"提示文本

**优先级**：P1

---

### US-08 右侧 Relevance 区块

作为用户，我希望 Relevance 区块自动显示与当前内容相关的笔记，以便在写作时发现关联知识。

**验收标准**：

Given 用户打开了一个笔记  
When 系统完成关联计算（≤ 2 秒）  
Then Relevance 区块显示 ≤ 5 条相关笔记（按日期标签匹配度排序）

Given Relevance 区块显示了相关笔记列表  
When 用户点击其中一条笔记  
Then 中央区域打开该笔记（当前笔记的编辑状态自动保存后切换）

- [ ] 关联计算基于当前笔记的日期和标签（Frontmatter tags 字段）
- [ ] 没有相关笔记时显示"暂无相关笔记"提示，不显示空列表
- [ ] 未打开任何笔记时，Relevance 区块显示"打开笔记后查看关联内容"

**优先级**：P1

## 范围界定

**In Scope**：

- 三栏固定布局（左/中/右）
- 四个默认 Tab（Daily / Private / Vault / Source）
- 自定义目录 Tab（右键固定，上限 6 个，可拖拽排序）
- 目录区域两种视图模式：树状（Tree）/ 平铺（Flat），按 Tab 独立记忆
- Pin 区块（单笔记固定）
- Tasks 区块（展示，详见 [04-task-management.md](04-task-management.md)）
- Relevance 区块（日期+标签关联）

**Out of Scope**：

- 移动端响应式适配：桌面端产品，不需要兼容移动端屏幕宽度；移动端接入通过 Telegram/Feishu Bot 实现
- 浏览器式多 Tab 并行展开：产品定位是单一专注工作区，左侧导航同时只有一个 Tab 处于激活状态
- 目录区域文件拖拽排序/移动：文件顺序由 Vault 文件系统决定；文件的移动和重命名由用户在系统文件管理器操作

## 非功能需求

- Tab 切换响应时间 ≤ 300ms（包含目录树重新渲染）
- 窗口最小可用尺寸：宽 900px × 高 600px
- 应用关闭前窗口尺寸和各面板宽度自动持久化，下次启动时恢复
