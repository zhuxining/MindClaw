# 功能需求规格：消息渠道与 Agent 调度 v1.0

## § 背景与目标

**背景**：MindClaw 作为本地桌面 AI 助理，需要从飞书等 IM 渠道接收消息并交由本地 Agent 智能处理。当前系统无消息接入能力，无法实现"消息入 → Gateway 标准化 → Bus 路由 → ACP 处理 → 结果出"的闭环。

**目标**：实现飞书消息接入、Gateway 标准化、MessageBus 统一路由、ACP Agent 调度的完整链路，让用户能在 MindClaw 中查看消息流和 Agent 处理结果。

核心数据流：**`im_channel` → `gateway` → `message_bus` → `acp`**

## § 功能描述

### Story 1：配置飞书连接

**作为** MindClaw 用户，**我希望** 在设置中配置飞书 App ID 和 Secret，**以便** 让 MindClaw 能够连接我的飞书账号获取消息。

**优先级**：P0

**验收标准**：

- [ ] 用户在设置页面输入飞书 App ID 和 App Secret
- [ ] 密钥保存到 Stronghold 安全存储中
- [ ] 点击"测试连接"后，系统调用飞书 API 验证凭证有效性
- [ ] 验证成功显示"连接成功"提示，失败显示具体错误原因
- [ ] 重新打开应用后，已保存的凭证自动加载

---

### Story 2：拉取飞书消息

**作为** MindClaw 用户，**我希望** MindClaw 自动拉取飞书中的新消息，**以便** 我不需要手动导入消息。

**优先级**：P0

**验收标准**：

- [ ] `im_channel/feishu` 每隔可配置的时间间隔（默认 30 秒）自动轮询飞书新消息
- [ ] 轮询间隔可在设置中调整（最小 10 秒，最大 300 秒）
- [ ] 已拉取的消息不会重复出现（基于 message_id 去重）
- [ ] 轮询失败时在 UI 中显示错误状态，不影响下一次轮询
- [ ] 用户可手动点击"刷新"按钮立即拉取消息

---

### Story 3：Gateway 消息标准化

**作为** MindClaw 用户，**我希望** 飞书消息经过 Gateway 标准化处理，**以便** 系统能统一处理不同来源的消息。

**优先级**：P0

**验收标准**：

- [ ] `gateway` 接收 `im_channel` 的 `RawMessage`，完成身份鉴权
- [ ] `gateway` 按渠道/用户维度进行限流检查
- [ ] `gateway` 将 `RawMessage` 转换为标准 `ChannelMessage`（包含 channel_id, sender_id, content, timestamp）
- [ ] 标准化后的消息投递到 `message_bus`
- [ ] 鉴权失败或限流触发的消息被拦截，记录日志

---

### Story 4：查看消息流

**作为** MindClaw 用户，**我希望** 在 MindClaw 界面中看到从飞书拉取的消息流，**以便** 了解有哪些新消息。

**优先级**：P1

**验收标准**：

- [ ] 消息以时间线方式展示，最新的在顶部
- [ ] 每条消息显示：发送者名称、消息内容、来源渠道、时间戳
- [ ] 支持消息内容文本展示（v1 不支持图片/文件等富媒体）
- [ ] 消息流自动更新（新消息到达后追加到列表）

---

### Story 5：消息自动路由到 Agent

**作为** MindClaw 用户，**我希望** 飞书消息自动发送给本地 Agent 处理，**以便** Agent 能自动帮我摘要、回复或执行任务。

**优先级**：P0

**验收标准**：

- Given 已配置飞书连接且 Agent 可用，When 飞书新消息到达 `message_bus`，Then `message_bus` 自动将消息路由到默认 Agent
- [ ] 消息到达后自动触发 Agent 处理（无需手动操作）
- [ ] Agent 处理期间消息显示"处理中"状态
- [ ] Agent 处理完成后结果显示在对应消息下方
- [ ] 处理失败时显示错误信息，支持手动重试

---

### Story 6：ACP Agent 执行

**作为** MindClaw 用户，**我希望** ACP 能正确执行 Agent 任务并返回结果，**以便** 获得智能处理输出。

**优先级**：P0

**验收标准**：

- [ ] `acp` 接收 `AgentRequest`，完成意图识别（Router）
- [ ] `acp` 进行任务规划（Planner），复杂任务拆分为子任务
- [ ] `acp` 执行动作（Executor），调用 Agent 完成处理
- [ ] `acp` 返回 `AgentResponse`，包含处理状态、输出内容、执行元数据
- [ ] 处理超时（默认 120s）时返回超时错误，支持取消

---

### Story 7：Agent 处理结果回写飞书

**作为** MindClaw 用户，**我希望** Agent 处理完消息后自动将结果回复到飞书会话中，**以便** 飞书中的对话者能看到 Agent 的回复。

**优先级**：P1

**验收标准**：

- Given Agent 处理完成并产生回复内容，When 回复内容非空，Then 系统通过 `gateway` → `im_channel/feishu` 发送回复到原始会话
- [ ] 回复消息包含原始消息的引用（回复模式）
- [ ] 回复失败时在 UI 中显示错误，支持手动重试
- [ ] 用户可在设置中关闭"自动回复飞书"开关

---

### Story 8：配置路由规则

**作为** MindClaw 用户，**我希望** 自定义消息路由规则（如指定关键词匹配），**以便** 控制哪些消息交给 Agent 处理。

**优先级**：P2

**验收标准**：

- [ ] 用户可创建路由规则：指定匹配条件（渠道、发送者、关键词）和对应的处理动作
- [ ] 规则支持简单的关键词匹配（包含/不包含）
- [ ] 规则按优先级排序，高优先级规则先匹配
- [ ] 无匹配规则的消息不触发 Agent 处理

## § 范围界定

### In Scope

- 飞书单渠道消息接入（拉取 + 发送）`im_channel/feishu`
- Gateway 消息标准化、鉴权、限流
- MessageBus 消息路由引擎
- ACP 协议 Agent 调用（Router + Planner + Executor）
- 基础消息流 UI（文本消息展示）
- 路由规则配置（v1 基础版：关键词匹配）
- 密钥 Stronghold 安全存储

### Out of Scope

| 排除项 | 理由 |
|--------|------|
| 飞书以外的消息渠道 | 蓝图 v2.0 规划，v1 先验证飞书单渠道；架构已预留扩展点 |
| 图片/文件等富媒体消息 | 增加复杂度，v1 聚焦文本消息 |
| WebSocket 实时推送 | v1 采用轮询，桌面应用无公网 IP |
| 多 Agent 并行处理 | v1 单 Agent 串行，降低复杂度 |
| 消息历史搜索 | 非核心路径，v2 考虑 |
| Agent 本身的实现 | 架构边界：ACP 只做桥接和执行调度 |
| ACP 技能插件系统 | v1.1 规划，v1 聚焦基础执行 |

## § 非功能需求

| 类别 | 约束 | 量化阈值 |
|------|------|---------|
| 性能 | 消息轮询响应时间 | 单次轮询 ≤ 5 秒 |
| 性能 | Gateway 标准化处理 | 单条消息 ≤ 100ms |
| 性能 | Agent 调用超时 | 可配置，默认 120 秒 |
| 安全 | 密钥存储 | 必须使用 Stronghold，不得明文存储 |
| 安全 | 网络请求范围 | 仅 `im_channel` 可发起外部 HTTP 请求 |
| 安全 | Gateway 鉴权 | 每条消息必须经过身份验证 |
| 可靠性 | 轮询失败恢复 | 连续失败 3 次后指数退避，最大间隔 300 秒 |
| 可靠性 | 消息不丢失 | `message_bus` 保证至少一次投递 |
| 兼容性 | 平台支持 | macOS（v1），Windows/Linux（v1.1） |
