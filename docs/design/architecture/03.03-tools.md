# MindClaw 技术架构设计 — Tools 层

> 完整架构文档索引见 [README.md](./README.md) | Agent 核心见 [03-agent-loop.md](./03-agent-loop.md)

## Tool 层架构

工具按实现性质分为两类：**原生工具**（Rust 实现，代码级控制）和 **MCP 工具**（外部服务，连接状态过滤）。

```
原生工具（Native，Schema 始终在 tools 数组，round 0 即可调用）
├── filesystem          → 文件读写（read/write/edit）
├── find_files          → glob 文件查找
├── search_content      → 正则内容搜索
├── shell               → 受限命令执行
├── knowledge           → KnowledgeService 工具包（见 03.05-services.md）
├── daily               → DailyService 工具包（见 03.05-services.md）
├── task                → TaskService 工具包（见 03.05-services.md）
└── capability_search   → 统一非原生能力搜索（MCP 工具 + Skills）

MCP 工具（Schema 不在初始 tools 数组，通过 capability_search 发现）
└── mcp_*               → mcp.toml 配置，仅成功连接的 server 的工具进入 CapabilityIndex

Skills（指令存入 CapabilityIndex，通过 capability_search 激活）
└── *.md skills         → 启动时扫描，description 做 embedding 存入 CapabilityIndex
```

**设计原则**：
- 原生工具无连接状态，代码级确定，Schema 始终可用；增删原生工具 = 代码修改
- MCP 工具有连接状态，只有**成功连接**的 server 的工具才进入索引；Schema 按需发现
- Skills 同为非原生能力，与 MCP 工具共享 `capability_search` 入口，激活路径不同（MCP → ToolRegistry，Skill → messages）
- 所有原生工具平等对待，不设"元工具"特殊分类

### PathGuard — 路径安全策略

类 Tauri Capability 模型的路径访问控制，供 FilesystemTool、FindFilesTool、SearchContentTool、ShellTool 共享：

| 特性         | 说明                                                |
| ------------ | --------------------------------------------------- |
| 主工作区     | `vault/` 作为默认 authorized root                   |
| 扩展授权     | `with_extra()` 追加用户通过 dialog 授权的路径       |
| 拒绝前缀     | `with_denied("private")` 拒绝 `private/` 路径       |
| 路径穿越防护 | 组件级 `PathBuf::starts_with()` 检查，防 `../` 逃逸 |
| 绝对路径处理 | 必须在某个 authorized root 内                       |

```rust
pub struct PathGuard {
    primary: PathBuf,           // vault root
    extra_roots: Vec<PathBuf>,  // 用户授权目录
    denied_prefixes: Vec<String>,
}
```

### ToolRegistry 与 CapabilityIndex

```
ToolRegistry（run 级活跃工具集）
├── 原生工具（启动时注册，始终存在）
└── 本次 run 通过 capability_search 激活的 MCP 工具（动态追加）

CapabilityIndex（全局非原生能力目录）
├── MCP 工具（仅来自当前成功连接的 server）
│       ├── 工具元数据：name、description、schema、server_name
│       └── 描述向量：embedding 供语义搜索
└── Skills（启动时扫描）
        ├── 元数据：name、description、file_path
        └── 描述向量：embedding 供语义搜索
```

**注册时机**：

- 启动时：原生工具注册到 `ToolRegistry`；MCP 工具连接成功后索引到 `CapabilityIndex`（不进 `ToolRegistry`）；Skills 扫描后索引到 `CapabilityIndex`
- MCP server 断开时：从 `CapabilityIndex` 移除该 server 的所有工具
- run 中：`capability_search` 查询 `CapabilityIndex` → MCP 工具延迟注册到 `ToolRegistry`，下一 round 可调用

**一个 round 的调用时延（仅 MCP 工具，Provider API 约束）**：`tools` 数组在每次 `chat_stream` 请求发出时固定，MCP 工具注册后需等到下一 round 才能被 LLM 调用：

```
round N:   capability_search("slack") → MCP tool 延迟注册 → 写入 ToolRegistry
round N+1: export_schemas() 包含新 Schema → LLM 可调用 slack_post_message
```

原生工具无此约束（始终在 tools 数组）。Skill 激活无此约束（指令直接注入 messages，当轮可读）。

**ToolRegistry 职责**：

- **并发控制**：Semaphore 限制并行工具执行数（默认 4）
- **Schema 导出**：每轮 `export_schemas()` 导出当前活跃工具集（原生 + 已激活 MCP）
- **批量执行**：并行执行多个 tool calls，单工具失败不中断其他工具
- **去重机制**：`(tool_name, canonical_args_json)` 签名防无限循环

### capability_search — 统一非原生能力搜索

`capability_search` 是原生工具，统一搜索 MCP 工具和 Skills，LLM 无需区分能力类型。

```
capability_search(query: String) -> Vec<CapabilityResult>

执行流程：
  1. 对 query 做语义搜索（embedding）+ 关键词匹配
  2. 同时检索 CapabilityIndex 中的 MCP 工具和 Skills
  3. 按匹配度排序，返回 Top K 结果
  4. 按 kind 分支激活：
     Mcp   → 路由条目追加到 ToolRegistry，下一 round 可调用
     Skill → Tier 2 instructions 注入 messages，标记 protected

CapabilityResult:
  ├── kind: Mcp { server_name, schema } | Skill { instructions }
  ├── name: String
  └── description: String
```

**激活路径差异**：

|          | MCP 工具                      | Skill                              |
| -------- | ----------------------------- | ---------------------------------- |
| 激活效果 | 追加到 ToolRegistry（可调用） | Tier 2 指令注入 messages           |
| 内容形式 | JSON Schema                   | Markdown 指令文本                  |
| 调用时延 | 1 round（Provider API 约束）  | 当轮即可读取指令                   |
| 持久化   | 不进 SessionHistory           | 进 messages，标记 protected        |

**典型工作流（MCP）**：

```
round 0: capability_search("发送 Slack 消息")
          → CapabilityIndex 返回 MCP tool: slack_post_message → 激活到 ToolRegistry

round 1: LLM 调用 slack_post_message(channel: "#dev", text: "...")
```

**典型工作流（Skill）**：

```
round 0: capability_search("处理 PDF 文件")
          → CapabilityIndex 返回 Skill: pdf-processing → 指令注入 messages（protected）

round 1: LLM 读取指令，调用 filesystem/shell 执行 PDF 操作
```

**约束**：capability_search 结果（MCP schema）不持久到 SessionHistory；每次 run 独立激活；若无匹配，返回空列表 + 提示。

### 工具执行边界

| 边界          | 规则                                           |
| ------------- | ---------------------------------------------- |
| 最大 round 数 | 单次 run 最多 8 个工具 round                   |
| 输出截断      | 超长输出在回写前截断                           |
| 敏感信息      | `token`/`api_key`/`password` 等模式脱敏        |
| 失败语义      | 工具失败返回结构化结果，不 poison session 历史 |

## 基础能力工具

### filesystem

文件读写操作，路径隔离通过 PathGuard。

| 操作    | 说明                                             | 安全约束          |
| ------- | ------------------------------------------------ | ----------------- |
| `read`  | 读取文件内容                                     | vault 内，max 1MB |
| `write` | 覆盖写入                                         | 自动创建父目录    |
| `edit`  | 局部编辑（insert/delete/replace/prepend/append） | 行级操作          |

**设计决策**：`list` 操作已移除，由 `find_files` 替代（`pattern: "*", max_depth: 1`）。

### find_files

基于 `ignore::WalkBuilder` 的 glob 文件查找，自动尊重 `.gitignore`。

| 参数          | 类型   | 说明                                  |
| ------------- | ------ | ------------------------------------- |
| `pattern`     | string | glob 模式，如 `*.md`, `**/*.rs`       |
| `path`        | string | 起始目录（相对 vault，空=根）         |
| `file_type`   | enum   | `any`/`file`/`directory`，默认 `file` |
| `max_depth`   | int    | 最大递归深度（1-20）                  |
| `max_results` | int    | 最多返回数量（默认 100，max 500）     |

**输出**：JSON `{ total: N, truncated: bool, results: ["rel/path", ...] }`

### search_content

基于 `grep-searcher` + `grep-regex` 的文件内容搜索。

| 参数             | 类型   | 说明                           |
| ---------------- | ------ | ------------------------------ |
| `pattern`        | string | 正则表达式（必需）             |
| `path`           | string | 搜索目录（相对 vault）         |
| `glob`           | string | 文件过滤 glob，如 `*.md`       |
| `case_sensitive` | bool   | 默认 false                     |
| `context_lines`  | int    | 上下文行数（0-10，默认 2）     |
| `max_results`    | int    | 最多匹配数（默认 50，max 200） |

**输出**：grep 风格文本

```
notes/2024/alpha.md
  12: ## Architecture
  13: This **architecture** document.
--
planning/roadmap.md
  5: The **architecture** will be finalized.
--
[23 matches in 4 files]
```

**截断**：整体输出硬截断 16KB；单端截断 5KB（head+tail 模式）。

### shell

受限 Shell 执行，基于 deny list + 路径穿越防护 + 环境隔离。

| 安全机制     | 说明                                                      |
| ------------ | --------------------------------------------------------- |
| Deny List    | `rm -rf`, `dd`, `shutdown`, `mkfs`, fork bomb 等 10+ 模式 |
| 路径穿越     | 命令字符串含 `../` 直接拒绝                               |
| 工作目录限制 | `working_dir` 必须在 vault 内（PathGuard 校验）           |
| 环境隔离     | `env_clear()` + 仅透传 SAFE_ENV_VARS（防 API key 泄露）   |
| 超时         | 默认 30s，最大 300s                                       |

**SAFE_ENV_VARS**：`PATH`, `HOME`, `TERM`, `LANG`, `USER`, `SHELL`, `TMPDIR` 等（平台相关）。

**输出**：head+tail 截断各 5KB，包含 exit code。

## MCP 集成 — 外部工具协议

MindClaw 作为 MCP Client，通过 **文件配置** 连接外部 MCP Server。代码内不再提供直接配置入口。

### 配置文件

路径：`{data_dir}/mcp.toml`

```toml
[[server]]
name = "git"

[server.transport]
type = "child_process"
command = "uvx"
args = ["mcp-server-git"]

[[server]]
name = "filesystem"

[server.transport]
type = "child_process"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me/docs"]

[[server]]
name = "github"

[server.transport]
type = "child_process"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = [["GITHUB_PERSONAL_ACCESS_TOKEN", "ghp_xxxx"]]
```

### 架构

```
McpBridgeManager::from_file(data_dir)
    ├── 读取 mcp.toml
    ├── 对每个 server: TokioChildProcess → serve() → RunningService<RoleClient>
    └── 注册 McpProxyTool 到 ToolRegistry

McpProxyTool
    ├── name() / description() / input_schema() → 来自 server list_tools
    └── execute() → 转发到 server.call_tool
```

### 失败策略

| 场景                 | 行为                             |
| -------------------- | -------------------------------- |
| mcp.toml 不存在      | 静默跳过，无 MCP 工具            |
| mcp.toml 解析失败    | warn 日志，继续启动（无 MCP）    |
| 单个 server 连接失败 | error 日志，不影响其他 server    |
| list_tools 失败      | error 日志，该 server 工具不注册 |

### 命名空间

MCP 工具直接使用 server 返回的 tool name，无额外前缀。如 `git_status`、`read_file`。

## Agent Hooks — 事件钩子系统

Hooks 是工具执行的**唯一业务拦截机制**（验证、审计、结果覆盖），在 Agent 执行关键节点提供**继续 / 显式变换 / 阻断**能力。工具的执行模式（Sequential/Parallel）通过 `Tool::execution_mode()` 声明，业务逻辑统一走 Hooks，两者职责不交叉。

### Hook 生命周期事件

| 事件点       | 触发时机     | 能力          |
| ------------ | ------------ | ------------- |
| SessionStart | 会话创建时   | 初始化设置    |
| PreMessage   | 处理消息前   | 修改/阻止消息 |
| PostMessage  | 处理消息后   | 副作用触发    |
| PreToolUse   | 工具调用前   | 验证/修改参数 |
| PostToolUse  | 工具调用后   | 审计/修改输出 |
| RunCompleted | Run 成功完成 | 清理/通知     |
| RunFailed    | Run 失败     | 错误处理      |
| SessionEnd   | 会话结束时   | 资源释放      |

### Hook 决策类型

- **Continue**：继续正常执行
- **Apply(patches)**：应用修改后继续
- **Block(reason)**：阻止执行并给出理由

## Agent Skills — 技能系统

Skill 是 Agent 能力的组合包，通过 `capability_search` 按需激活，遵循渐进式披露设计。

### 三级渐进式披露

```
Tier 1: CapabilityIndex（启动时索引，不注入 system prompt）
├── name + description 做 embedding，存入 CapabilityIndex
├── 通过 capability_search 发现，~0 tokens 常驻开销
└── 取代原"全量目录注入 system prompt"方案

Tier 2: Instructions（capability_search 激活时注入）
├── 完整 SKILL.md body 作为 tool_result 注入 messages
├── 标记 protected，免于 context compaction
└── <5000 tokens (recommended)

Tier 3: Resources（按需加载）
├── scripts, references, assets
├── LLM 通过 filesystem 工具按需读取
└── Varies by usage
```

### Skill Discovery — 运行时扫描

**扫描路径**（按优先级）：

| 优先级 | 来源          | 路径                        |
| ------ | ------------- | --------------------------- |
| 1      | Builtin       | `src-tauri/skills/*.md`     |
| 2      | Project       | `<project>/.agents/skills/` |
| 3      | User          | `~/.agents/skills/`         |
| 4      | Compatibility | `~/.claude/skills/`         |

**冲突处理**：Project > User > Builtin。同名 skill 高优先级覆盖低优先级。

### Skill 文件格式

标准 `SKILL.md`（YAML frontmatter + Markdown body）：

```markdown
---
name: pdf-processing
description: "Extract PDF text, fill forms, merge files."
version: "1.0.0"
---

# PDF Processing

## When to use this skill

Use this skill when the user needs to work with PDF files...

## Available operations

...
```

### Skill 上下文保护

Skill instructions（Tier 2）一旦加载，**免于 context compaction**：

- Skill content 标记为 protected，pruning 算法跳过
- 防止 mid-conversation 丢失 skill instructions

### 与 SubAgent 的集成

Skill 通过 `context: fork` 声明在独立 SubAgent 中运行：

```yaml
---
name: complex-analysis
description: "Multi-step data analysis"
context: fork # → 转换为临时 MarkdownSubAgent
---
```

`context: fork` 是语法糖：创建临时 SubAgent，避免污染主对话上下文。

## ToolRegistry — 常驻 vs 可发现

### 默认常驻 Schema（5 个）

| 工具             | 用途                        |
| ---------------- | --------------------------- |
| `filesystem`     | 文件系统读写编辑            |
| `find_files`     | glob 文件查找               |
| `search_content` | 正则内容搜索                |
| `shell`          | 受限命令执行                |
| `mcp_*`          | 外部 MCP 工具（按配置动态） |

### Schema 层级控制

```
Agent::run()（内部上下文组装时）
    │
    ├── resident_schemas() → 发送给 LLM（5 个）
    │
    └── MCP tools → 按 mcp.toml 配置注册
```

常驻 Schema 数量固定为 5（不含 MCP），避免上下文膨胀；MCP 工具数量无限制，按配置加载。

## 依赖 Crate

| 工具           | 依赖                          | 用途                            |
| -------------- | ----------------------------- | ------------------------------- |
| find_files     | `ignore`, `globset`           | .gitignore 感知遍历 + glob 匹配 |
| search_content | `grep-searcher`, `grep-regex` | 正则搜索引擎                    |
| MCP            | `rmcp`                        | MCP 协议 client/server          |
| shell          | `tokio::process`              | 异步进程执行                    |

**注意**：`ripgrep` 和 `fd-find` 是 CLI binary crate，无 library API，未使用；改用其底层子 crate (`grep-searcher`, `ignore`)。
