# MCP — 外部能力适配

---

## § 职责定位

MCP 模块负责外部 MCP Server 的配置、连接生命周期、工具发现和权限过滤；远端工具的 Tool 适配与调用路径优先复用 Rig `rmcp::McpTool`。它不负责 Agent 路由、上下文构建、工具权限决策或工具执行循环。

---

## § 在新架构中的位置

MCP 属于 Adapter Layer：

- MindClaw 持有 `mcp.toml` 配置、stdio / streamable-http 连接和启用工具过滤。
- Rig `McpTool` 把远端 MCP tool 暴露为 `ToolDyn`。
- AgentRunner 将 MCP 工具与内置工具一起装入 Rig `ToolSet/ToolServerHandle`。

MCP 不属于 `AgentProfile`，也不由 `AgentLoop` 直接调用。

---

## § 核心对象

**MCPManager**

- 读取 MCP 配置
- 管理 Server 连接与关闭
- 每次构建工具范围时刷新远端工具列表
- 为启用的远端工具创建 Rig `McpTool`

**Rig McpTool**

- 由 Rig 提供的 MCP 工具适配器
- 负责工具定义、参数传递、调用结果转换和错误传播
- 以普通 `ToolDyn` 进入 Runner 的工具集合

---

## § 与工具系统的关系

```text
MCP Server
-> MCPManager
-> rig::tool::rmcp::McpTool
-> ToolSet / ToolServerHandle
-> Rig Agent
-> AgentRunner
```

MCP 工具和内置工具在执行层面等价，只是来源不同。

---

## § 设计决策与权衡

| 决策问题 | 选择 | 放弃的替代方案 | 理由 |
|---------|------|--------------|------|
| MCP 处于哪一层？ | Adapter Layer | Agent Runtime Core | MCP 是外部协议接入，不是核心运行时语义 |
| MCP 工具如何暴露？ | 通过 Rig `McpTool` 进入 ToolSet | 自研 `MCPToolAdapter` / `ToolRegistry` | Rig 已提供 MCP tool 适配，减少重复实现 |
| MCP 权限由谁控制？ | AgentProfile + tool filtering + MCP server enabled_tools | MCPManager 单独决定全部策略 | 权限控制应该统一，不应让单个 adapter 成为策略源 |
