## Context Pipeline — 可插拔上下文组装

上下文组装仍采用可插拔 `ContextSource` 管线，但其调用时机固定为：Session 解析完成、SessionCommand 未命中之后，由 `agent.run()` 内部显式触发。

### System Prompt 组装结构

```
┌─────────────────────────────────────────────────────────────┐
│ 固定层（启动时加载）                                         │
├─────────────────────────────────────────────────────────────┤
│ SOUL.md / IDENTITY.md / USER.md / Tool Schema              │
├─────────────────────────────────────────────────────────────┤
│ 动态层（每次 run 按需注入）                                  │
├─────────────────────────────────────────────────────────────┤
│ MemoryRecallSource                                          │
│ RAGKnowledgeSource                                          │
│ ConversationHistorySource                                   │
│ UserMessageSource                                           │
└─────────────────────────────────────────────────────────────┘
```

### ContextSource Trait 与 Pipeline

```rust
// src-tauri/src/agent/context.rs

pub struct ContextFragment {
    pub role: MessageRole,
    pub content: String,
    pub token_estimate: usize,
    pub label: String,
}

/// 每次 run 的请求级数据，仅含本次请求必须的上下文。
/// 基础设施依赖（memory、db、services）由各 ContextSource 在构造时注入。
/// history 由 AgentLoop 通过 session_mgr.compressed_history() 预提取后传入。
pub struct ContextInput {
    pub inbound: InboundMessage,
    pub history: Vec<ChatMessage>,  // 已压缩的对话历史，由 AgentLoop 预提取
}

#[async_trait]
pub trait ContextSource: Send + Sync {
    fn name(&self) -> &str;
    fn priority(&self) -> i32;
    fn enabled(&self) -> bool { true }
    async fn inject(
        &self, input: &ContextInput, budget: usize,
    ) -> Result<Vec<ContextFragment>, AppError>;
}

/// Agent 发给 Provider 的完整上下文，由 ContextPipeline 组装产出。
pub struct AgentContext {
    pub system_prompt: String,
    pub messages: Vec<ChatMessage>,
    pub fragments: Vec<ContextFragment>,
}

pub struct ContextPipeline {
    sources: Vec<Arc<dyn ContextSource>>,
    total_budget: usize,
    budget_allocations: HashMap<String, usize>,
}
```

构建逻辑：按 `priority` 顺序遍历 source，在各自 budget 内注入 fragment；超预算时优先削减 RAG，再压缩历史，最后截断观察类内容。

### 内置源映射

各 Source 在构造时注入所需的基础设施依赖（`Arc<...>`），运行时仅接收 `ContextInput`（inbound + history）。

| Source                      | Priority | 默认预算 | 构造依赖                | 注入方式                           |
| --------------------------- | -------- | -------- | ----------------------- | ---------------------------------- |
| `SystemPromptSource`        | 0        | ~2K      | `Arc<ServiceContainer>` | 固定加载 SOUL/IDENTITY/USER        |
| `RAGKnowledgeSource`        | 10       | ~10K     | `Arc<DbState>`          | `search_with_rerank` Top N         |
| `MemoryRecallSource`        | 20       | ~2K      | `Arc<MemoryManager>`    | relevance + importance 排序        |
| `ConversationHistorySource` | 30       | ~50K     | —（来自 input.history） | 直接注入（AgentLoop 已预压缩）     |
| `UserMessageSource`         | 100      | ~1K      | —（来自 input.inbound） | 始终最后                           |

### Token 预算管理

| 策略       | 实现                                             |
| ---------- | ------------------------------------------------ |
| 知识库注入 | L0 粗筛 → L1 overview 重排序 → Top N             |
| 对话历史   | 近 5 轮完整 + 早期摘要                           |
| Token 预算 | 由 Provider 配置决定，通过 `max_tokens` 参数传入 |
