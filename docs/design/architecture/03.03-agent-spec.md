# AgentRunSpec 与 AgentRunResult

---

## § 职责定位

本模块负责定义 AgentLoop 与 AgentRunner 之间的数据契约（执行配置和执行结果），不负责构建逻辑、执行逻辑或持久化逻辑。

---

## § 边界与实体

**输入（AgentRunSpec 的来源）**：由 AgentLoop 调用 ContextPipeline、SessionManager、ToolRegistry 收集各部分数据，汇总构建为一个不可变 Spec 传入 AgentRunner。

**输出（AgentRunResult 的去向）**：AgentRunner 返回后，AgentLoop 将其拆解：消息链写入 SessionManager，响应文本发布到 MessageBus，Token 用量供监控。

**核心实体**：

**AgentRunSpec**：一次 Agent 执行的完整声明式配置，构建后不可修改。
关键属性：

- 消息历史（三层上下文合并后的有序消息列表，含 System、User、Assistant、ToolResult 四类消息）
- 工具集（本次运行可用的工具 JSON Schema 列表）
- LLM 模型标识（如 `claude-opus-4-6`）
- 迭代上限（防止无限循环的硬性上限）
- 并行工具开关（控制工具并发执行还是顺序执行）
- 工具错误策略（遇到工具错误是立即中止还是继续让 LLM 决策）
关系：由 AgentLoop 创建，传入 AgentRunner；Runner 只读取 Spec，不修改。

**AgentRunResult**：一次完整执行的结构化输出记录。
关键属性：

- 最终响应文本（经 `finalize_content` 后处理，已剥离 think 标签）
- 完整消息链（含所有迭代的 LLM 响应和工具结果消息，用于 Turn 持久化）
- 使用的工具名称列表（去重后，供日志和展示）
- 停止原因（`Completed` / `MaxIterations` / `ToolError` / `Cancelled`，枚举类型）
- Token 用量统计（所有迭代的累积 prompt tokens 和 completion tokens）
关系：由 AgentRunner 创建并返回给 AgentLoop 处理。

**Message**：消息列表中的单条消息，表示一轮对话中的一段内容。
关键属性：角色类型（决定消息语义）、文本内容、工具调用列表（仅 Assistant 消息有）、媒体附件（仅 User 消息有）。
关系：多条 Message 构成 AgentRunSpec 的消息历史；AgentRunner 在每次迭代后向列表追加新消息（LLM 响应 + 工具结果）。

## § Spec 构建来源

```
ContextPipeline    SessionManager     ToolRegistry     AppConfig
     │                   │                │               │
     ▼                   ▼                ▼               ▼
  三层上下文          历史 Turn         工具 Schema      模型标识
  System 消息        User/Assistant                      迭代上限
     │                   │                │               │
     └───────────────────┴────────────────┴───────────────┘
                                 │
                         AgentRunSpec（不可变）
                                 │
                          AgentRunner.run()
                                 │
                         AgentRunResult（完整记录）
```

---

## § 关键流程

1. AgentLoop 调用 ContextPipeline 获得三层上下文消息列表（Core 系统消息 + Dynamic 系统消息）。
2. AgentLoop 从 SessionManager 获取已压缩的历史 Turn 消息列表。
3. AgentLoop 向 ToolRegistry 获取当前可用工具的 JSON Schema 列表。
4. AgentLoop 按场景（对话/子代理）设置迭代上限和工具执行策略，构建不可变 AgentRunSpec。
5. AgentRunner 执行迭代，每轮向 Spec 消息列表追加新消息（不修改 Spec，而是维护本地消息副本）。
6. AgentRunner 完成后，将最终消息链、Token 用量、停止原因打包为 AgentRunResult 返回。

---

## § 停止原因语义

| 停止原因 | 触发条件 | AgentLoop 处理方式 |
|---------|---------|-----------------|
| `Completed` | LLM 响应不含工具调用（正常完成） | 将响应持久化为 Turn，标记成功 |
| `MaxIterations` | 达到 Spec 声明的迭代上限 | 持久化已有内容，记录超限日志 |
| `ToolError` | 工具执行失败且 `fail_on_tool_error=true` | 持久化失败信息，可选通知用户 |
| `Cancelled` | AgentLoop 主动取消（如收到 /stop 命令） | 丢弃未完成的内容，释放锁资源 |

## § 设计决策与权衡

| 决策问题 | 选择 | 放弃的替代方案 | 理由 |
|---------|------|--------------|------|
| AgentRunSpec 是否允许执行中修改？ | 构建后不可变 | 允许 AgentLoop 在迭代间修改 Spec | 不可变保证执行可预测，同一 Spec 可在不同 Hook 下复现；可变 Spec 会引入 AgentLoop 和 Runner 的隐式耦合 |
| AgentRunResult 是否包含完整消息链？ | 是，包含所有迭代的消息 | 仅返回最终响应文本 | 完整消息链用于 Turn 持久化（包含工具调用记录）；只返回文本则 SessionManager 无法保存工具使用历史 |
| 停止原因如何表达？ | 枚举类型（Completed / MaxIterations / ToolError / Cancelled） | 布尔值 + 错误字符串 | 枚举在 match 时编译期强制处理所有情况，防止 AgentLoop 遗漏特定停止场景 |
| 工具执行策略如何传递给 Runner？ | Spec 字段（`parallel_tools`、`fail_on_tool_error`） | Runner 方法参数 | Spec 是完整执行契约，策略属于执行配置的一部分；方法参数会分散配置，不便于日志记录和重现 |
| 如何支持不同场景的 Spec 构建？ | Builder 模式（`AgentRunSpec::builder()`） | 直接构造所有字段 | Builder 模式提供默认值和验证；不同场景（对话/子代理/测试）只覆盖必要字段，减少重复代码 |
| 消息历史是否需要压缩标记？ | 是，标记哪些消息是压缩后的摘要 | 不标记，统一处理 | 标记允许 AgentLoop 在持久化时区分原始消息和摘要，UI 层可据此展示不同的视觉效果 |
| 如何验证 Spec 的合法性？ | Builder 模式在 build() 时验证 | 不验证，运行时出错 | 提前验证在编译期或构建期发现问题，而非 LLM 调用时才发现配置错误 |
| Spec 是否需要支持克隆？ | 是，实现 Clone | 不实现 | 测试场景需要克隆 Spec 进行多次对比执行；克隆使测试更灵活 |
