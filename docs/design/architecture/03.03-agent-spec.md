# AgentRunSpec 与 AgentRunResult

> 声明式执行配置与结构化执行结果

## 设计哲学

**AgentRunSpec** 和 **AgentRunResult** 是 Agent 核心的两个核心数据类型，体现了以下设计原则：

- **声明式配置**：AgentRunSpec 是一个冻结的、自包含的数据类，声明了执行所需的一切参数
- **不可变性**：Spec 在构建后不可修改，确保执行的可预测性
- **完整性**：Runner 所需的一切都预先提供，不会越界获取
- **结构化输出**：AgentRunResult 提供完整的执行记录，便于持久化和分析

## AgentRunSpec

### 结构定义

```rust
/// 声明式 Agent 执行配置
///
/// 这是一个冻结的数据类，包含执行引擎所需的每一个参数。
/// 由于使用了不可变设计，该规范在构建后既节省内存又可预测。
pub struct AgentRunSpec {
    /// 预组装的消息历史记录，包含系统提示词和用户输入
    /// 详见下方 Message 类型和三层架构
    pub messages: Vec<Message>,

    /// 本次运行可用的工具集合
    pub tools: ActiveTools,

    /// LLM 模型标识符（如 "claude-3-5-sonnet"）
    pub model: String,

    /// 工具调用周期的硬性上限（防止无限循环）
    /// 默认：8
    pub max_iterations: usize,

    /// 采样温度覆盖值
    /// None 表示使用模型默认值
    pub temperature: Option<f32>,

    /// 每次 LLM 调用的最大补全 Token 数
    /// None 表示无限制
    pub max_tokens: Option<usize>,

    /// 是否并行执行工具调用
    /// true：并发执行（默认）
    /// false：顺序执行
    pub parallel_tools: bool,

    /// 工具错误是否立即中止循环
    /// true：第一个工具错误立即中止
    /// false：错误作为消息返回，LLM 可重试（默认）
    pub fail_on_tool_error: bool,
}

/// 聊天消息，支持三层架构
pub enum Message {
    /// 系统消息（第 1 层 Core + 第 2 层 Dynamic）
    System {
        content: String,
    },

    /// 用户消息（第 3 层 User）
    User {
        content: String,
        /// 媒体附件（图片等）
        attachments: Vec<Attachment>,
    },

    /// Assistant 消息
    Assistant {
        content: String,
        /// 工具调用请求
        tool_calls: Option<Vec<ToolCall>>,
    },

    /// 工具执行结果
    ToolResult {
        /// 工具名称
        name: String,
        /// 工具输出内容
        content: String,
        /// 对应的 tool_call ID
        tool_call_id: String,
    },
}

impl Message {
    pub fn system(content: impl Into<String>) -> Self {
        Self::System { content: content.into() }
    }

    pub fn user(content: impl Into<String>) -> Self {
        Self::User {
            content: content.into(),
            attachments: vec![],
        }
    }

    pub fn assistant(content: impl Into<String>) -> Self {
        Self::Assistant {
            content: content.into(),
            tool_calls: None,
        }
    }

    pub fn assistant_with_tools(content: impl Into<String>, tool_calls: &[ToolCall]) -> Self {
        Self::Assistant {
            content: content.into(),
            tool_calls: Some(tool_calls.to_vec()),
        }
    }

    pub fn tool_result(name: impl Into<String>, content: impl Into<String>, tool_call_id: impl Into<String>) -> Self {
        Self::ToolResult {
            name: name.into(),
            content: content.into(),
            tool_call_id: tool_call_id.into(),
        }
    }
}
```

### 字段详解

#### messages

预组装的消息列表，格式遵循 LLM Provider 的聊天格式：

**构建顺序（三层架构）**：

1. System 消息（第 1 层 Core：身份、引导文件、工具 Schema）
2. System 消息（第 2 层 Dynamic：Identity、Memory、Knowledge、Skills）
3. 会话历史（User/Assistant 交替）
4. 当前 User 消息（第 3 层 User：运行时上下文 + 用户输入）

**三层架构详见**：[03.06-context-building.md](./03.05-agent-context.md)

**核心命题**：记忆是 Agent 的，知识是共同的

- Memory（Agent 私有）：第 2 层 Dynamic 注入
- Knowledge（人机共有）：第 2 层 Dynamic 注入

#### tools

本次运行可用的工具快照，与全局 ToolCatalog 分离：

```rust
pub struct ActiveTools {
    /// 本次运行可用的工具绑定
    pub bindings: Vec<ToolBinding>,
}

pub struct ToolBinding {
    pub name: String,
    pub description: String,
    pub parameters: serde_json::Value,  // JSON Schema
    pub handler: Arc<dyn ToolHandler>,
}
```

**设计理由**：

- 允许每次运行动态调整可用工具
- 防止运行间工具状态相互影响
- 支持上下文感知工具（如需要 channel 信息的工具）

#### max_iterations

硬性上限，防止无限循环：

- **默认值**：8
- **范围**：1-32
- **触发**：达到上限后返回 `StopReason::MaxIterations`

**典型场景**：

- 简单问答：1-2 轮
- 文件操作：3-5 轮
- 复杂任务：6-8 轮

#### parallel_tools

控制工具执行模式：

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| `true`（默认） | 并发执行（`join_all`） | 独立的只读操作（如多个 read_file） |
| `false` | 顺序执行（`for` 循环） | 有依赖关系的操作（如先写后读） |

**并发限制**：全局信号量限制并发工具执行数（默认 4）

#### fail_on_tool_error

错误处理策略：

| 值 | 行为 | 适用场景 |
|----|------|----------|
| `false`（默认） | 错误作为消息返回，LLM 可分析并重试 | 大多数场景 |
| `true` | 第一个错误立即中止循环 | 严格模式、测试 |

### 构建示例

#### 标准对话

```rust
let spec = AgentRunSpec {
    messages: self.build_messages(&message, &session).await,
    tools: ActiveTools::standard(),  // fs, shell, web 等

    max_iterations: 8,
    temperature: None,
    max_tokens: None,
    parallel_tools: true,
    fail_on_tool_error: false,

```

```rust
let spec = AgentRunSpec {

    tools: ActiveTools::minimal(),  // 仅必要工具

    max_iterations: 4,  // 限制迭代次数

    max_tokens: Some(2000),  // 限制输出长度
    parallel_tools: true,
    fail_on_tool_error: false,

```

## AgentRunResult

### 结构定义

```rust
/// 结构化 Agent 执行结果
///
/// 包含执行期间所发生情况的完整记录
pub struct AgentRunResult {
    /// 清理并完成最终定稿的文本响应
    /// 如果出错，可能是错误消息或 fallback 内容
    pub content: String,

    /// 包含所有中间工具调用轮次的完整消息列表
    /// 可用于持久化到会话历史
    pub messages: Vec<Message>,

    /// 执行期间调用的工具名称的有序列表
    pub tools_used: Vec<String>,

    /// 所有 LLM 调用的聚合 Token 使用量
    pub usage: TokenUsage,

    /// 停止原因：Completed、MaxIterations、ToolError、Cancelled
    pub stop_reason: StopReason,

    /// 当 stop_reason 为 ToolError 或 Error 时的错误描述
    pub error: Option<String>,

    /// 每次工具调用的结构化事件轨迹
    /// 用于遥测和调试
    pub tool_events: Vec<ToolEvent>,
}
```

### 字段详解

#### content

最终用户可见的文本响应：

- **正常完成**：LLM 的最终回复（已剥离 think 标签）
- **最大迭代**：提示消息（如 "Reached maximum iterations (8)"）
- **工具错误**：错误描述（如 "Tool error: file not found"）

#### messages

完整的对话记录，包含三层架构构建的消息：

```
[0] System 消息（第 1 层 Core - 缓存稳定）
      SOUL.md / USER.md / AGENTS.md / 工具 Schema

[1..K] System 消息（第 2 层 Dynamic - 每次请求变化）
      [1] ## 当前角色\n{identity}
      [2] ## 相关记忆\n- 记忆 1\n- 记忆 2
      [3] ## 相关知识\n- 知识 1（来源：xxx.md）
      [4] ## 可用技能\n- skill1: 描述

[K+1..N] 历史消息（User / Assistant 交替）

[N+1] User 消息（第 3 层 User - 运行时上下文 + 用户输入）
       [当前时间：2026-04-03 14:32 Friday +0800，平台：macOS]
       
       用户输入内容

[N+2] Assistant 消息（可能含 tool_calls）
[N+3..] ToolResult 消息
...（多轮迭代）
[M] 最终 Assistant 消息
```

**三层架构详见**：[03.06-context-building.md](./03.05-agent-context.md)

**用途**：

- 持久化到 Session 历史
- 调试和审计
- 支持核心命题：记忆是 Agent 的，知识是共同的

#### tools_used

工具调用顺序记录：

```rust
vec!["read_file", "read_file", "shell", "read_file"]
```

**用途**：

- 显示给用户（"使用了 3 个工具"）
- 分析和统计
- 计费（如按工具调用计费）

#### usage

Token 使用量统计：

```rust
pub struct TokenUsage {
    pub prompt_tokens: usize,      // 输入 token
    pub completion_tokens: usize,  // 输出 token
    pub total_tokens: usize,       // 总计
}
```

**聚合逻辑**：多轮迭代的累加

#### stop_reason

停止原因枚举：

```rust
pub enum StopReason {
    /// LLM 返回了不包含工具调用的内容，循环自然中断
    Completed,

    /// 达到 max_iterations 上限
    MaxIterations,

    /// 工具错误且 fail_on_tool_error=true
    ToolError,

    /// 执行被取消（如用户 /stop）
    Cancelled,

    /// LLM 返回错误
    Error,
}
```

#### tool_events

工具调用事件轨迹：

```rust
pub struct ToolEvent {
    pub name: String,
    pub tool_call_id: String,
    pub status: ToolStatus,  // Started, Succeeded, Failed
    pub duration_ms: u64,
    pub input_tokens: usize,
    pub output_tokens: usize,
}

pub enum ToolStatus {
    Started,
    Succeeded,
    Failed { error: String },
}
```

**用途**：

- 遥测和监控
- 调试工具性能
- 生成执行报告

### 构建场景

#### 正常完成

```rust
AgentRunResult {
    content: "我已经读取了 README.md，这是一个 Rust 项目...".to_string(),

    stop_reason: StopReason::Completed,
    error: None,
    tool_events: vec![/* 工具事件 */],

```

#### 最大迭代

```rust

    content: "Reached maximum iterations (8).".to_string(),
    messages: vec![/* 8 轮完整消息 */],
    tools_used: vec!["read_file", "shell", "read_file", /* ... */],
    usage: TokenUsage { prompt_tokens: 8000, completion_tokens: 4000, total_tokens: 12000 },
    stop_reason: StopReason::MaxIterations,
    error: Some("Max iterations reached".to_string()),
    tool_events: vec![/* 所有工具事件 */],
}
```

#### 工具错误

```rust
AgentRunResult {
    content: "Tool error: File not found: /path/to/file".to_string(),
    messages: vec![/* 到错误点的消息 */],
    tools_used: vec!["read_file".to_string()],
    usage: TokenUsage { prompt_tokens: 100, completion_tokens: 50, total_tokens: 150 },
    stop_reason: StopReason::ToolError,
    error: Some("File not found: /path/to/file".to_string()),
    tool_events: vec![
        ToolEvent {
            name: "read_file".to_string(),
            tool_call_id: "call_123".to_string(),
            status: ToolStatus::Failed { error: "File not found".to_string() },
            duration_ms: 10,
            input_tokens: 10,
            output_tokens: 0,
        }
    ],
}
```

## 使用模式

### 模式 1：标准对话

```rust
// AgentLoop 中
let spec = self.build_spec(&message, &session).await;
let mut hook = LoopHook::new(self.bus.clone(), session_key);
let result = self.runner.run(spec, &mut hook).await;
self.session_manager.append_turn(&session_key, &result).await;
```

### 模式 2：后台任务

```rust
// SubAgent 中
let spec = AgentRunSpec::background(&task);
let mut hook = NoOpHook;
let result = self.runner.run(spec, &mut hook).await;
self.send_result(&task.session_key, result).await;
```

### 模式 3：测试

```rust
// 测试中
let spec = AgentRunSpec::test(&messages, &tools);
let mut hook = TestHook::new();
let result = runner.run(spec, &mut hook).await;
assert_eq!(result.stop_reason, StopReason::Completed);
assert!(result.tools_used.contains(&"read_file".to_string()));
```

## 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Spec 可变性 | 不可变 | 确保执行可预测，避免运行时修改 |
| Result 完整性 | 包含完整消息链 | 便于持久化和调试 |
| 工具事件 | 结构化 | 支持遥测和分析 |
| Token 统计 | 聚合 | 便于成本计算和监控 |
| 错误处理 | 枚举 + Option | 明确区分成功/失败场景 |
| 消息三层架构 | Core / Dynamic / User | 平衡缓存稳定性与动态上下文，支持核心命题 |
