# MindClaw 技术架构设计 — Tools 层

> 完整架构文档索引见 [README.md](./README.md) | Agent 核心见 [03-agent-loop.md](./03-agent-loop.md)

## Tool 层架构

Agent 上下文常驻仅 **4 个 Tool Schema**，业务操作通过 `operations` 元工具按需发现，避免上下文膨胀。

```
Tools（常驻上下文）
├── filesystem   → 文件系统操作
├── shell        → 受限命令执行
├── mcp_client   → 外部 MCP 工具
└── operations   → 元工具（按需发现 Services + Memory 操作）
```

### ToolRegistry

工具注册中心，管理工具生命周期和执行：

- **并发控制**：Semaphore 限制并行工具执行数（默认 4）
- **Schema 管理**：动态生成 JSON Schema 供 Provider 使用
- **批量执行**：并行执行多个 tool calls，单工具失败不中断其他工具
- **去重机制**：`(tool_name, canonical_args_json)` 签名防无限循环

### 工具执行边界

| 边界 | 规则 |
|------|------|
| 最大回合数 | 单次 run 最多 8 轮工具回合 |
| 输出截断 | 超长输出在回写前截断 |
| 敏感信息 | `token`/`api_key`/`password` 等模式脱敏 |
| 失败语义 | 工具失败返回结构化结果，不 poison session 历史 |

### 基础能力工具

| 工具 | 操作 | 安全约束 |
|------|------|---------|
| **filesystem** | read/write/append/list/move/delete | `vault/` 内限定，`private/` 禁入 |
| **shell** | exec (白名单) | 白名单命令，30s 超时，输出截断 |
| **mcp_client** | call_tool, list_tools | MCP 协议调用外部工具服务 |
| **operations** | list/call | Services 与 Memory 的唯一业务操作通道 |

## Operations — 业务操作元工具

`operations` 连接 Agent 与 Services/Memory。操作 Schema 不常驻上下文，仅在 `list` 时返回；Agent 已知常用操作名时可直接 `call`。

### 已注册操作

| 操作名 | 类别 | 说明 |

## MCP 集成 — 外部工具协议

MindClaw 作为 MCP Client，连接外部 MCP Server 获取工具能力。每个 MCP tool 独立注册到 ToolRegistry。

### MCP 架构

```
McpServerManager
    ├── connects to MCP servers (stdio / HTTP)
    ├── discovers available tools via tools/list
    └── registers McpTool instances to ToolRegistry

ToolRegistry
    ├── resident: filesystem, shell, operations
    └── discoverable: mcp__{server}__{tool} (按需发现)
```

### MCP 工具命名空间

工具名格式：`mcp__{server}__{tool}`，例如 `mcp__filesystem__read_file`

### 自动注册策略

```toml
[mcp.servers.filesystem]
transport = { type = "stdio", command = "npx", args = [...] }
auto_register = ["read_file", "list_directory"]  # 常驻白名单
# auto_register = "none"   # 全部按需发现
# auto_register = "all"    # 全部常驻
```

## Agent Hooks — 事件钩子系统

Hooks 在 Agent 执行关键节点提供拦截能力，支持**继续 / 显式变换 / 阻断**。

### Hook 生命周期事件

| 事件点 | 触发时机 | 能力 |
|--------|---------|------|
| SessionStart | 会话创建时 | 初始化设置 |
| PreMessage | 处理消息前 | 修改/阻止消息 |
| PostMessage | 处理消息后 | 副作用触发 |
| PreToolUse | 工具调用前 | 验证/修改参数 |
| PostToolUse | 工具调用后 | 审计/修改输出 |
| RunCompleted | Run 成功完成 | 清理/通知 |
| RunFailed | Run 失败 | 错误处理 |
| SessionEnd | 会话结束时 | 资源释放 |

### Hook 决策类型

- **Continue**：继续正常执行
- **Apply(patches)**：应用修改后继续
- **Block(reason)**：阻止执行并给出理由

### Shell 命令钩子（轻量级）

无需编译的配置化 Hook：

```toml
[[hooks]]
name = "audit-shell"
hook_point = "PreToolUse"
matcher = "shell"
command = "/usr/bin/logger"
args = ["mindclaw-hook", "tool=${tool_name}"]
timeout_ms = 1000
failure_policy = "fail_open"  # 或 fail_closed
```

## Agent Skills — 技能系统

Skill 是 Agent 能力的组合包，遵循渐进式披露设计。

### 三级渐进式披露

```
Tier 1: Catalog (Session Start)
├── name + description 注入 system prompt
└── ~50-100 tokens per skill

Tier 2: Instructions (On Activation)
├── 完整 SKILL.md body
├── 由 ContextSource 在预算允许时注入
└── <5000 tokens (recommended)

Tier 3: Resources (On Demand)
├── scripts, references, assets
├── 模型通过 file-read 按需加载
└── Varies by usage
```

### Skill Discovery — 运行时扫描

**扫描路径**（按优先级）：

| 优先级 | 来源 | 路径 |
|--------|------|------|
| 1 | Builtin | `src-tauri/skills/*.md` |
| 2 | Project | `<project>/.agents/skills/` |
| 3 | User | `~/.agents/skills/` |
| 4 | Compatibility | `~/.claude/skills/` |

**冲突处理**：Project > User > Builtin。同名 skill 高优先级覆盖低优先级。

### Skill 文件格式

标准 `SKILL.md`（YAML frontmatter + Markdown body）：

```markdown
---
name: pdf-processing
description: "Extract PDF text, fill forms, merge files."
version: "1.0.0"
---

# PDF Processing

## When to use this skill
Use this skill when the user needs to work with PDF files...

## Available operations
...
```

### Skill 上下文保护

Skill instructions（Tier 2）一旦加载，**免于 context compaction**：
- Skill content 标记为 protected，pruning 算法跳过
- 防止 mid-conversation 丢失 skill instructions

### 与 SubAgent 的集成

Skill 通过 `context: fork` 声明在独立 SubAgent 中运行：

```yaml
---
name: complex-analysis
description: "Multi-step data analysis"
context: fork  # → 转换为临时 MarkdownSubAgent
---
```

`context: fork` 是语法糖：创建临时 SubAgent，避免污染主对话上下文。

## ToolRegistry — 常驻 vs 可发现

### 默认常驻 Schema（4 个）

| 工具 | 用途 |
|------|------|
| `filesystem` | 文件系统操作 |
| `shell` | 受限命令执行 |
| `mcp_client` | 外部 MCP 工具 |
| `operations` | 元工具（发现 Services/MCP/Agents） |

### 可发现工具

- **MCP tools**：`mcp__{server}__{tool}`
- **Service operations**：`svc__{service}__{operation}`
- **Delegate agents**：`agent__{type}`

### Schema 层级控制

```
AgentLoop::run_once()
    │
    ├── resident_schemas() → 发送给 LLM（4 个）
    │
    └── operations list → 返回所有可发现工具
        │
        └── LLM 调用 operations call → 执行任意可发现工具
```

常驻 Schema 数量固定为 4，避免上下文膨胀；可发现工具数量无限制，按需使用。
