# MindClaw 技术架构设计 — SubAgent

> 完整架构文档索引见 [README.md](./README.md) | Agent 核心见 [03-agent-loop.md](./03-agent-loop.md)

## 层级模型

```
SOUL（灵魂，唯一）          用户始终面对同一个 SOUL
  └── IDENTITY（分身，多个） system prompt 中列出角色，LLM 第一轮自行选择
        └── SubAgent（助手） 执行中临时 spawn，无身份无人格
```

- **SOUL**：定义 Agent 的核心人格和价值观，全局唯一
- **IDENTITY**：SOUL 在不同场景下的角色面（如代码审查、研究、写作），不单独做路由推理，而是在 system prompt 中以角色列表呈现，LLM 在第一轮 reasoning 中自然选择
- **SubAgent**：IDENTITY 在执行过程中的临时助手，纯工具性

## SubAgent — 异步委派

SubAgent 是 IDENTITY 的**异步助手**——由主 Agent 在执行过程中自主决定 spawn，在独立上下文中运行，不共享也不污染主 Agent 的对话历史。

SubAgent 没有预定义模板，system prompt 在 spawn 时动态构建（含 workspace、时间上下文、Skills 摘要），任务内容作为 user message 注入。

**两条核心约束：**

- **不递归**：SubAgent 的 ToolRegistry 不注册 `spawn_subagent`，不能再派生 SubAgent
- **结果回注**：SubAgent 完成后，结果以 system inbound message 回注到**发起 session**，由主 Agent（以 SOUL 口吻）向用户汇报

### 执行机制

每次 spawn 创建一个独立的 mini AgentLoop（`AgentRunner.run()`）：

1. 动态构建 system prompt（workspace + 时间上下文 + Skills 摘要）
2. `task` 字符串作为 user message
3. 使用受限工具集（无 `spawn_subagent`）
4. 收集最终 assistant 文本
5. 通过 `bus.publish_inbound(system_message)` 将结果回注，触发主 Agent 汇报

### 结果回注格式

```
[Subagent '{label}' completed successfully]

Task: {task}

Result:
{result}

Summarize this naturally for the user. Keep it brief (1-2 sentences).
```

失败时状态为 `failed`，result 为错误摘要或已完成步骤列表。主 Agent 收到后自行判断如何处理——向用户汇报，或静默记录。

### 生命周期

**主 Agent 永远不等 SubAgent。** spawn 是非阻塞的——如果需要同步等待结果，直接在当前 run 内用普通工具完成即可，不需要 SubAgent。SubAgent 存在的意义就是"甩出去，不阻塞当前 run"。

```
Run N:  用户消息
          → 主 Agent 执行中，决定 spawn subagent
          → spawn_subagent 工具立即返回"已启动"
          → 主 Agent 告知用户"正在后台处理"
          → Run N 正常结束
                                          ╭─ SubAgent 后台独立运行 ─╮
                                          │  独立上下文、受限工具集  │
                                          │  ...执行中...            │
                                          ╰──────────┬───────────────╯
                                                     │ 完成
                                                     ▼
Run N+1: SubAgent 结果回注 inbound queue（Follow-up 语义）
          → 触发新 run
          → 主 Agent 收到结果，自行决定：
              • 用户在等 → 汇报结果
              • 后台任务 → 简短告知或静默
```

**关键设计**：

- spawn 时不指定"结果如何处理"——主 Agent 在 Run N+1 收到结果后**自行判断**，如同助手做完事来汇报，你再决定要不要跟别人说
- 回注消息走标准 inbound 路径（Follow-up 语义），与用户消息排队规则一致
- 若主 Agent 正在执行其他 run，SubAgent 结果进 `follow_up_queue` 等待

### 调度方式

| 场景              | 触发方                    |
| ----------------- | ------------------------- |
| 主动探索/规划     | `spawn_subagent` 工具调用 |
| 会话结束摘要      | Event Bus                 |
| 定时知识提炼/日报 | Cron 调度层               |

### 核心类型

```rust
// src-tauri/src/agent/subagent/manager.rs

pub struct SubagentManager {
    provider: Arc<dyn Provider>,
    workspace: PathBuf,
    bus: Arc<MessageBus>,
    model: String,
    running_tasks: DashMap<String, JoinHandle<()>>,
    session_tasks: DashMap<String, HashSet<String>>,
}

impl SubagentManager {
    /// Spawn a subagent to execute a task in the background.
    /// Returns a user-facing acknowledgement string.
    pub async fn spawn(
        &self,
        task: String,
        label: Option<String>,
        origin: Origin,              // channel + chat_id，用于回注目标
        session_key: Option<String>, // 用于 cancel_by_session
    ) -> String;

    /// Cancel all subagents for the given session. Returns count cancelled.
    pub async fn cancel_by_session(&self, session_key: &str) -> usize;

    pub fn get_running_count(&self) -> usize;
}
```

### SpawnSubagentTool

将 `SubagentManager.spawn()` 包装为 Tool，供 LLM 主动调用：

```rust
pub struct SpawnSubagentTool {
    manager: Arc<SubagentManager>,
    origin: Origin,      // 注入调用来源（channel + chat_id）
    session_key: String, // 注入当前 session
}

#[async_trait]
impl Tool for SpawnSubagentTool {
    fn name(&self) -> &str { "spawn_subagent" }
    // 参数：task (string), label (string?)
    async fn execute(&self, input: ToolInput) -> AppResult<ToolOutput>;
}
```

主 Agent 注册此工具；SubAgent 构建时**不注册**，防止递归委派。

### 与 Skill 的关系

| 维度   | Skill                              | SubAgent                               |
| ------ | ---------------------------------- | -------------------------------------- |
| 定位   | Prompt-side guidance（上下文注入） | Independent execution（独立执行）      |
| 上下文 | 注入主会话 system prompt           | 独立上下文，不回写主会话               |
| 输出   | 影响主代理行为                     | 结果回注 MessageBus，触发主 Agent 汇报 |

### CapabilityProfile（安全边界）

```rust
pub struct CapabilityProfile {
    pub allowed_tools: Vec<String>,
    pub fs_scope: FsScope,
    pub network: NetworkPolicy,
    pub max_tokens: Option<u32>,
    pub max_tool_calls: u32,  // 默认 15
    pub timeout_ms: u64,
}
```

capabilities 由主 Agent 在 spawn 时指定，SubAgent 无法自行扩权。
