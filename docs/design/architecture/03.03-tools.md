## Tool 层 — Agent 可用工具

Agent 上下文常驻仅 4 个 Tool Schema，业务操作通过 `operations` 元工具按需发现和调用，避免上下文膨胀。

```
Tools（常驻上下文，4 个 Schema）
├── filesystem   → 文件系统操作
├── shell        → 受限命令执行
├── mcp_client   → 外部 MCP 工具
└── operations   → 元工具（按需发现 Services + Memory 操作）
```

### ToolRegistry

```rust
// src-tauri/src/tools/mod.rs

pub struct ToolCall {
    pub id: String,
    pub name: String,
    pub arguments: Value,
}

pub struct ToolResultMessage {
    pub tool_call_id: String,
    pub content: String,
    pub is_error: bool,
}

pub struct ToolRegistry {
    tools: HashMap<String, Arc<dyn Tool + Send + Sync>>,
    concurrency: Arc<Semaphore>,  // 限制并行工具执行数（默认 4）
}

impl ToolRegistry {
    /// 创建新的 ToolRegistry
    pub fn new() -> Self;

    /// 设置并发限制
    pub fn with_concurrency_limit(self, limit: usize) -> Self;

    /// 注册工具（统一使用 Arc）
    pub fn register(&mut self, tool: Arc<dyn Tool + Send + Sync>);

    /// 获取工具
    pub fn get(&self, name: &str) -> Option<&(dyn Tool + Send + Sync)>;

    /// 返回所有注册工具的 JSON Schema 定义（供 Provider 的 tools 参数使用）
    pub fn schemas(&self) -> Vec<ToolSchema>;

    /// 并行执行多个 tool calls（Semaphore 限制并发），每个 call 接受 CancellationToken。
    /// 单个工具失败返回 is_error=true 的结果，不中断其他工具。
    pub async fn execute_calls(
        &self, calls: Vec<ToolCall>, cancel: CancellationToken,
    ) -> Result<Vec<ToolResultMessage>, AppError>;

    /// 执行单个工具
    pub async fn execute(&self, name: &str, input: ToolInput) -> AppResult<ToolOutput>;
}
```

**设计说明**：`ToolRegistry` 统一使用 `Arc<dyn Tool>` 存储工具，支持多线程共享。初始化时直接用 `Arc::new()` 创建工具，Skill 注入时直接传递已有的 `Arc`。

### 工具执行边界

| 边界 | 规则 |
|------|------|
| 最大回合数 | 单次 run 最多 8 轮工具回合 |
| 工具去重 | 使用 `(tool_name, canonical_args_json)` 计算签名，防无限循环 |
| 输出截断 | 超长工具输出在回写上下文和持久化前截断 |
| 敏感信息 | `token` / `api_key` / `password` 等模式统一脱敏 |
| 失败语义 | 工具失败返回结构化结果，不直接 poison session 历史 |

### 基础能力工具

| 工具 | 操作 | 安全约束 |
|------|------|---------|
| **filesystem** | read/write/append/list/move/delete | `vault/` 内限定，`private/` 禁入 |
| **shell** | exec (白名单) | 白名单命令，禁管道/重定向，30s 超时，输出截断 |
| **mcp_client** | call_tool, list_tools | MCP 协议调用外部工具服务 |
| **operations** | list/call | Services 与 Memory 的唯一业务操作通道 |

### Operations — 业务操作元工具

`operations` 连接 Agent 与 Services/Memory。操作 Schema 不常驻上下文，仅在 `list` 时返回；Agent 已知常用操作名时可直接 `call`。

## MCP 集成 — 外部工具协议

MindClaw 作为 MCP Client，连接外部 MCP Server 获取工具能力。与业界最佳实践对齐，**每个 MCP tool 独立注册到 ToolRegistry**，而非封装为单一 `mcp_client` 工具。

### MCP 架构

```
McpServerManager
    ├── connects to MCP servers (stdio / HTTP)
    ├── discovers available tools via tools/list
    └── registers McpTool instances to ToolRegistry

ToolRegistry
    ├── resident: filesystem, shell, operations
    └── discoverable: mcp__{server}__{tool} (按需发现)
```

### MCP Server Manager

```rust
// src-tauri/src/tools/mcp.rs

/// MCP 传输层配置
pub enum McpTransport {
    Stdio { command: String, args: Vec<String> },
    Http { url: String },
}

/// MCP Server 配置
pub struct McpServerConfig {
    pub name: String,
    pub transport: McpTransport,
    pub auto_register: McpAutoRegister,
}

/// MCP 工具自动注册策略
pub enum McpAutoRegister {
    None,               // 全部按需发现
    All,                // 全部注册为常驻
    Only(Vec<String>),  // 仅白名单工具注册为常驻
}

/// MCP Server 管理器
pub struct McpServerManager {
    servers: HashMap<String, McpServerConfig>,
    clients: HashMap<String, Arc<McpClient>>,
}

impl McpServerManager {
    /// 连接所有配置的服务器并发现工具
    pub async fn discover_and_register(&self, registry: &mut ToolRegistry) -> Result<(), AppError>;
}
```

### McpTool — 独立 Tool 实现

```rust
/// 从 MCP Server 动态发现的工具
pub struct McpTool {
    server_name: String,
    tool_name: String,
    description: String,
    schema: Value,
    client: Arc<McpClient>,
}

#[async_trait]
impl Tool for McpTool {
    fn name(&self) -> &str {
        // 命名空间格式：mcp__{server}__{tool}
        &self.full_name  // e.g., "mcp__filesystem__read_file"
    }

    fn description(&self) -> &str { &self.description }
    fn input_schema(&self) -> Value { self.schema.clone() }

    async fn execute(&self, input: ToolInput) -> AppResult<ToolOutput> {
        // 通过 MCP 协议调用远端工具
        self.client.call_tool(&self.tool_name, input.parameters).await
    }
}
```

### MCP 工具发现

MCP tools 默认**不常驻上下文**，通过 `operations` 元工具按需发现：

```json
// operations list 返回
{
  "namespaces": {
    "mcp": [
      { "name": "mcp__filesystem__read_file", "description": "..." },
      { "name": "mcp__filesystem__write_file", "description": "..." }
    ],
    "services": [...],
    "agents": [...]
  }
}
```

用户可通过配置将常用 MCP tools 提升为常驻：

```toml
# settings.toml
[mcp.servers.filesystem]
transport = { type = "stdio", command = "npx", args = ["-y", "@modelcontextprotocol/server-filesystem", "/vault"] }
auto_register = ["read_file", "list_directory"]  # 常驻工具白名单
```

约定：

- `auto_register = "none"`：全部走按需发现
- `auto_register = "all"`：该 server 的全部 tools 常驻注册
- `auto_register = ["read_file", "list_directory"]`：仅白名单常驻，其余仍通过 `operations` 发现

## Agent Hooks — 事件钩子系统

Hooks 在 Agent 执行关键节点提供拦截能力，支持**继续 / 显式变换 / 阻断**。为保证可组合性，修改必须通过结构化 patch 表达，而不是依赖 `&mut Context` 的隐式副作用。

### Hook 生命周期事件

```rust
// src-tauri/src/agent/hooks.rs

pub enum HookPoint {
    SessionStart,   // 会话创建时
    PreMessage,     // 处理消息前（可修改/阻止）
    PostMessage,    // 处理消息后（副作用触发）
    PreToolUse,     // 工具调用前（可验证/修改参数）
    PostToolUse,    // 工具调用后（可审计/修改输出）
    RunCompleted,   // Run 成功完成
    RunFailed,      // Run 失败
    SessionEnd,     // 会话结束时
}
```

### Hook 修改模型

```rust
pub enum HookPatch {
    ReplaceMessage { content: String },
    ReplaceToolInput { input: Value },
    /// 整体替换工具输出，包含 `is_error` 标志。
    ReplaceToolOutput { output: ToolOutput },
    AddMetadata { key: String, value: String },
}
```

### Hook 决策类型

```rust
pub enum HookDecision {
    /// 继续正常执行
    Continue,
    /// 应用 patch 后继续；多个 hook 按 priority 顺序依次合并
    Apply(Vec<HookPatch>),
    /// 阻止执行并给出理由
    Block(String),
}
```

### Hook Trait

```rust
pub enum HookPayload {
    Message { content: String },
    ToolUse { tool_name: String, input: Value },
    ToolResult { tool_name: String, output: ToolOutput },
    Lifecycle,
}

pub struct HookContext {
    pub session_id: String,
    pub hook_point: HookPoint,
    pub payload: HookPayload,
    pub metadata: HashMap<String, String>,
}

#[async_trait]
pub trait Hook: Send + Sync {
    fn name(&self) -> &str;
    fn hook_point(&self) -> HookPoint;
    fn priority(&self) -> i32 { 0 }  // 数值越小越先执行

    async fn execute(&self, ctx: &HookContext) -> Result<HookDecision, AppError>;
}
```

### HookRegistry

```rust
pub struct HookRegistry {
    hooks: Vec<Arc<dyn Hook>>,  // Arc: 运行期共享，支持长期持有、反复调用、动态启停
}

impl HookRegistry {
    pub fn register(&mut self, hook: Arc<dyn Hook>);

    /// 执行指定事件点的所有 hooks
    /// 遇到 Block 立即返回；Apply 按优先级顺序依次合并
    pub async fn run_hooks(
        &self,
        point: HookPoint,
        ctx: HookContext,
    ) -> Result<HookDecision, AppError>;
}
```

**设计说明**：`Hook` 使用 `Arc` 存储，因为钩子是运行期对象，会被长期持有、反复调用。`Arc` 支持共享配置、动态启停、多执行链复用同一个 hook。

合并规则：

- 多个 `Apply` 顺序执行，后一个 patch 基于前一个 patch 的结果
- 同一字段发生冲突时，后执行的高优先级 hook 覆盖前者
- 每次 patch 应用后记录审计日志，支持回放与故障排查

### Hook 触发点在 AgentLoop 中的位置

```
run_once():
  1. Session get_or_create ──► run_hooks(SessionStart)
  2. Agent Command interception
  3. ► run_hooks(PreMessage) ◄
     └── 可 Block（阻止处理）或 Apply（修改消息内容）
  4. ContextPipeline.build()
  5. Provider chat_stream()
  6. 工具循环内：
     ├── ► run_hooks(PreToolUse) ◄
     │   └── 可 Block（阻止工具执行）或 Apply（修改参数）
     ├── tools.execute_calls()
     └── ► run_hooks(PostToolUse) ◄
         └── 可 audit / modify output
  7. Session append
  8. ► run_hooks(PostMessage) ◄
  9. RunCompleted / RunFailed ──► run_hooks(RunCompleted/RunFailed)
  10. Session close ──► run_hooks(SessionEnd)
```

### Shell 命令钩子（受控执行）

无需编译的轻量级 Hook，通过配置启用；但必须使用**结构化命令定义**，禁止直接执行模板化 shell 字符串。

```rust
pub enum HookFailurePolicy {
    FailOpen,    // hook 执行异常时仅记录日志
    FailClosed,  // hook 执行异常时阻断主流程
}

pub struct CommandHook {
    pub name: String,
    pub hook_point: HookPoint,
    pub matcher: Option<String>,  // 工具名正则匹配（仅 PreToolUse/PostToolUse）
    pub command: String,          // 可执行文件绝对路径
    pub args: Vec<String>,        // 结构化参数，支持 ${session_id} 等变量插值
    pub env: HashMap<String, String>,
    pub cwd: Option<PathBuf>,
    pub timeout_ms: u64,
    pub priority: i32,
    pub failure_policy: HookFailurePolicy,
}
```

```toml
# settings.toml
[[hooks]]
name = "audit-shell"
hook_point = "PreToolUse"
matcher = "shell"
command = "/usr/bin/logger"
args = ["mindclaw-hook", "tool=${tool_name}", "input=${tool_input_json}"]
timeout_ms = 1000
priority = 100
failure_policy = "fail_open"

[[hooks]]
name = "policy-block-network-write"
hook_point = "PreToolUse"
matcher = "shell|mcp__.*__write.*"
command = "/Users/me/.mindclaw/hooks/check-policy"
args = ["--tool", "${tool_name}", "--input", "${tool_input_json}"]
timeout_ms = 2000
priority = 10
failure_policy = "fail_closed"
```

安全要求：

- 不经 shell 解析，不支持 `$(...)`、管道、重定向、通配符展开
- 变量插值仅发生在 `args/env` 值内，且按参数边界传递
- 可配置允许的可执行文件目录，默认仅允许运行受信任路径
- `fail_closed` 仅用于策略/审批类 hook；审计类 hook 默认 `fail_open`

Command hook 的退出码映射到 `HookDecision`：

- `0` → Continue
- `2` → Block（stderr/stdout 简述作为理由）
- 其他 → 按 `failure_policy` 处理：`FailOpen` 记录错误后继续，`FailClosed` 阻断主流程

## Agent Skills — 技能系统

Skill 是 Agent 能力的组合包，遵循 [Agent Skills 标准](https://agentskills.io) 的三级渐进式披露设计：Catalog → Instructions → Resources。

### 核心原则：渐进式披露

```
Tier 1: Catalog (Session Start)
├── name + description 注入 system prompt
└── ~50-100 tokens per skill

Tier 2: Instructions (On Activation)
├── 完整 SKILL.md body
├── 由 ContextSource 在预算允许时直接注入
└── <5000 tokens (recommended)

Tier 3: Resources (On Demand)
├── scripts, references, assets
├── 模型通过 file-read 按需加载
└── Varies by usage
```

### Skill Discovery — 运行时扫描

MindClaw 支持**双模式**：内置 skills（编译期嵌入）+ 运行时扫描（文件系统）。

**扫描路径**（按优先级排序）：

| 优先级 | 来源 | 路径 | 说明 |
|--------|------|------|------|
| 1 | Builtin | `src-tauri/skills/*.md` | 编译期嵌入，开箱即用 |
| 2 | Project | `<project>/.agents/skills/` | 项目级自定义 |
| 3 | User | `~/.agents/skills/` | 用户级共享 |
| 4 | Compatibility | `~/.claude/skills/` | 兼容现有生态 |

**冲突处理**：Project > User > Builtin。同名 skill 高优先级覆盖低优先级，记录 warning 日志。

**信任检查**：Project-level skills 来自仓库，首次扫描时提示用户确认信任，防止恶意代码注入。

```rust
// src-tauri/src/agent/skill_discovery.rs

pub struct SkillDiscovery {
    builtin: HashMap<String, SkillDoc>,
    project: HashMap<String, SkillDoc>,
    user: HashMap<String, SkillDoc>,
}

impl SkillDiscovery {
    /// 扫描所有来源
    pub async fn scan_all(&mut self, project_root: &Path) -> Result<(), AppError> {
        // 1. 内置 skills（编译期）
        self.load_builtin();

        // 2. User-level: ~/.agents/skills/
        if let Ok(dir) = home_dir().join(".agents/skills").canonicalize() {
            self.scan_directory(&dir, SkillSource::User).await?;
        }

        // 3. Project-level: <project>/.agents/skills/（需信任确认）
        let project_skills = project_root.join(".agents/skills");
        if project_skills.exists() && self.is_project_trusted(project_root) {
            self.scan_directory(&project_skills, SkillSource::Project).await?;
        }

        // 4. 兼容：~/.claude/skills/
        if let Ok(dir) = home_dir().join(".claude/skills").canonicalize() {
            self.scan_directory(&dir, SkillSource::Compatibility).await?;
        }

        Ok(())
    }

    /// 按优先级解析 skill
    pub fn resolve(&self, name: &str) -> Option<&SkillDoc> {
        self.project.get(name)
            .or_else(|| self.user.get(name))
            .or_else(|| self.builtin.get(name))
    }

    /// 收集所有技能用于 Catalog（Tier 1）
    pub fn collect_catalog(&self) -> Vec<SkillCatalogItem> {
        // 按优先级合并，去重
    }
}

#[derive(Debug, Clone, Copy)]
pub enum SkillSource {
    Builtin,
    Project,
    User,
    Compatibility,  // .claude/skills/
}
```

### Skill 文件格式

标准 `SKILL.md` 格式（YAML frontmatter + Markdown body）：

```markdown
---
name: pdf-processing
description: "Extract PDF text, fill forms, merge files. Use when handling PDFs."
version: "1.0.0"
compatibility: Python 3.9+, PyPDF2
---

# PDF Processing

## When to use this skill
Use this skill when the user needs to work with PDF files...

## Available operations
...

## Bundled resources
- `scripts/extract.py`: Text extraction script
- `references/pdf-spec-summary.md`: PDF format reference
```

**解析容错**：

- YAML 解析失败 → 跳过 skill，记录 error
- `name` 不匹配目录名 → warning，继续加载
- `description` 缺失 → 跳过 skill（无法披露）
- 未引号的冒号值（如 `description: Use when: the user...`）→ 自动添加引号重试

### 三级披露实现

#### Tier 1: Catalog

Session start 时注入 system prompt：

```rust
// SkillsOverviewSource (ContextSource)
pub struct SkillsOverviewSource {
    catalog: Vec<SkillCatalogItem>,
}

#[async_trait]
impl ContextSource for SkillsOverviewSource {
    async fn inject(&self, _ctx: &ContextBuildContext, _budget: usize)
        -> Result<Vec<ContextFragment>, AppError> {

        let content = format!(
            "Available skills:\n\n{}",
            self.catalog.iter()
                .map(|s| format!("- {}: {}", s.name, s.description))
                .collect::<Vec<_>>()
                .join("\n")
        );

        Ok(vec![ContextFragment::system(content, "skills_catalog")])
    }
}
```

#### Tier 2: Instructions

Skill instructions 不作为 Tool 暴露，而是作为**上下文能力**注入：

```rust
pub struct SkillsOverviewSource {
    catalog: Vec<SkillCatalogItem>,
    builtin_docs: HashMap<String, SkillDoc>,
}

#[async_trait]
impl ContextSource for SkillsOverviewSource {
    async fn inject(&self, _ctx: &ContextBuildContext, budget: usize)
        -> Result<Vec<ContextFragment>, AppError> {

        let content = render_skills_context(&self.catalog, &self.builtin_docs, budget);
        Ok(vec![ContextFragment::system(content, "skills_catalog")])
    }
}
```

设计原则：

- Skill 是 prompt-side guidance，不是 callable tool
- 小型内置技能可在预算允许时直接注入全文
- 大型外部技能仅注入 Catalog，具体资源仍通过文件系统按需读取

#### Tier 3: Resources

Skill instructions 中的相对路径解析为绝对路径，模型通过 `filesystem` 工具按需读取：

```
skill 内容引用："Use `scripts/extract.py` to process PDFs"
                    ↓
模型调用：filesystem read_file(path: "/home/user/.agents/skills/pdf-processing/scripts/extract.py")
                    ↓
返回脚本内容，执行后获得结果
```

### 激活方式

**Model-driven（主要）**：
模型看到 Catalog → 在预算允许时直接获得内置 skill instructions → 按 skill 指南调用 `operations` 或读取资源

**User-explicit（辅助）**：
用户输入 `/skill pdf-processing` → Agent Command 拦截 → 直接注入 skill content

### Skill 上下文保护

Skill instructions（Tier 2）一旦加载，应**免于 context compaction**：

- Skill content 标记为 protected，pruning 算法跳过
- 或通过结构化标签 `<skill_content>` 识别并保留
- 防止 mid-conversation 丢失 skill instructions 导致行为退化

### 双模式技能架构

```
SkillRegistry
├── Builtin Skills (StandardSkillsBundle)
│   ├── Compile-time embedded via include_str!()
│   ├── Always available (even in sandboxed env)
│   └── Tier 1/2/3 supported
│
└── Runtime Skills (SkillDiscovery)
    ├── Project-level: .agents/skills/
    ├── User-level: ~/.agents/skills/
    ├── Compatibility: ~/.claude/skills/
    └── Trust check for project-level
```

**Code-based Skills**（Rust trait）：

- 通过 `Skill` trait 实现
- 编译期类型安全
- 适合核心能力（如内置 ContextSource / Hook / Operation）

**Prompt-based Skills**（Markdown）：

- 运行时扫描加载
- 零编译、即时修改
- 适合用户自定义、生态共享

### 与 SubAgent 的集成

Skill 通过 `context: fork` 声明在独立 SubAgent 中运行：

```yaml
---
name: complex-analysis
description: "Multi-step data analysis"
context: fork  # → 转换为临时 MarkdownSubAgent
model: claude-3-5-haiku
---
```

`context: fork` 是语法糖：Skill content 作为 system prompt → 创建临时 MarkdownSubAgent → `dispatch_parallel` → 返回结果给主会话。避免污染主对话上下文，适合复杂多步骤 workflow。

## ToolRegistry — 工具注册与 Schema 管理

ToolRegistry 管理所有可用工具，支持**常驻**与**可发现**两种注册模式。

### 常驻 vs 可发现

```rust
pub struct ToolRegistry {
    tools: HashMap<String, Arc<dyn Tool + Send + Sync>>,
    resident_tools: HashSet<String>,  // 常驻工具名集合
    concurrency: Arc<Semaphore>,
}

impl ToolRegistry {
    /// 注册工具（统一使用 Arc）
    pub fn register(&mut self, tool: Arc<dyn Tool + Send + Sync>);

    /// 获取常驻工具的 Schema（发送给 LLM）
    pub fn resident_schemas(&self) -> Vec<ToolSchema>;

    /// 获取所有工具的 Schema（用于 operations list）
    pub fn all_schemas(&self) -> Vec<ToolSchema>;
}
```

### 默认常驻 Schema（4 个）

| 工具 | 用途 |
|------|------|
| `filesystem` | 文件系统操作 |
| `shell` | 受限命令执行 |
| `mcp_client` | 外部 MCP 工具 |
| `operations` | 元工具（发现 Services/MCP/Agents） |

### 可发现工具

- **MCP tools**：`mcp__{server}__{tool}` 命名空间
- **Service operations**：`svc__{service}__{operation}` 命名空间
- **Delegate agents**：`agent__{type}` 命名空间

### Schema 层级控制

```
AgentLoop::run_once()
    │
    ├── resident_schemas() → 发送给 LLM（4 个）
    │
    └── operations list → 返回所有可发现工具
        │
        └── LLM 调用 operations call → 执行任意可发现工具
```

常驻 Schema 数量固定为 4，避免上下文膨胀；可发现工具数量无限制，按需使用。
